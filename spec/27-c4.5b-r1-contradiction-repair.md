Controlled fixture:

```text

            attempt-terminal-outcome=SUCCEEDED
Evidence B: VALID / EXACT_OBSERVATION / attempt a1
            attempt-terminal-outcome=FAILED
```

Independent oracle:

```text

semantic commit allowed = false
```

Observed C1:

```text

```

Per policy sharing common C1 authority, PR #77 measured ACR=1/6, SSER=1/6, and one O4 operation. The measurement is preserved closed/unmerged and is not rewritten by this repair.

## Root cause

`Evidence.claim` is human-readable opaque text. The semantic core previously had no explicit fact identity/value with which to determine that two individually VALID observations described the same semantic fact but asserted incompatible values.

Parsing `claim` text is deliberately rejected as a repair strategy. Free-form textual similarity or syntax is not semantic authority.

## Representation extension

`Evidence` gains two optional fields at the end of its constructor so existing positional and keyword construction remains compatible:

```text
claim_key:   Optional[str] = None
claim_value: Optional[str] = None
```

They obey an all-or-none invariant and must be non-empty strings when present.

`claim_key` is the explicit stable identity of the asserted semantic fact. It is expected to be sufficiently qualified to identify the fact independently of physical locality or text, for example:

```text
attempt:a1:terminal-outcome
```

`claim_value` is the asserted value, for example `SUCCEEDED` or `FAILED`.

The original `claim` field remains diagnostic/provenance text and is never parsed by contradiction logic.

## Contradiction semantics

For an action at time `now`, the semantic core considers structured claims contradictory when at least two supplied Evidence objects:

```text
have structured claim metadata
share claim_key
have different claim_value
status == VALID
authority >= REQUIRED_AUTHORITY[action]
are not expired by valid_until
satisfy max_age when a consumer supplies one
```

The minimal repair intentionally does not derive contradiction from free text and does not introduce a new scope-filtered contradiction rule. A fully qualified `claim_key` identifies the semantic fact. The measured A1 case is same-scope, so the repair result does not depend on unresolved scope-policy questions.

## Correctness-sensitive vs performance behavior

For `finalize`, `consume_state`, and `commit_migration`, contradictory structured Evidence fails closed through the existing `InsufficientEvidence` path before semantic authority changes.

`reconcile(...)` reports `AMBIGUOUS` for contradictory structured Evidence for any action.

Performance-only direct Evidence requirements such as `rank_endpoint` retain degradable behavior: a caller may still receive sufficient valid Evidence from `require_evidence(...)` even when `reconcile(...)` reports `AMBIGUOUS`. This preserves the governing distinction that correctness fails closed while performance may degrade.

## Relevance filtering

A conflicting item does not create a contradiction merely by existing if it is ineligible for the action because it is:

```text
non-VALID
below the action's required authority
expired by valid_until
older than a supplied max_age
```

This prevents stale or insufficient observations from vetoing an otherwise valid semantic fact solely because their structured value differs.

## Mechanical core extraction

The pre-repair `continuity/core.py` blob `ead30cf3c4b900b9d2db81f25f12327d3d6fea21` is preserved byte-for-byte as `continuity/core_base.py`. The new `continuity/core.py` subclasses that exact implementation and overrides only the Evidence requirement/reconciliation methods needed for this repair.

This extraction is mechanical provenance isolation, not a semantic rewrite: all non-Evidence C1 behavior is inherited unchanged from the exact pre-repair blob. Review should treat the small wrapper plus `Evidence` representation extension as the semantic delta.

## Regression requirements

The repair test suite requires:

- structured metadata is both-present or both-absent and non-empty;
- same key + different valid sufficient values reconciles `AMBIGUOUS`;
- contradictory finalization rejects with Request still RUNNING and Attempt still CURRENT;
- identical structured values remain `MATCHED` and finalize successfully;
- state consumption contradiction returns false;
- migration contradiction rejects without changing Binding authority;
- stale, expired, below-authority, or max-age-ineligible conflicting items do not create false contradictions;
- performance direct `require_evidence` remains degradable while reconciliation is `AMBIGUOUS`;
- mutually exclusive-looking opaque `claim` strings without structured metadata are not parsed heuristically.
