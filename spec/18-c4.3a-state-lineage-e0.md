# 1. Research boundary

C4.3a evaluates the deterministic State-lineage safety claim without changing C1, C2, C3, or the C4.1 correctness contract.

The canonical RQ2 question is whether causal State lineage prevents reuse of locally attractive but logically incompatible State. The primary safety obligations are:

```text
WBRR
WSCR
SSER
```

The closed baseline distinction is preserved exactly:

```text
B0  request/load only
B1  candidate-key cache locality
B2  session affinity + candidate locality
B3  exact StateID + precise State location, causally blind
B4  complete Continuity context + C1 state_compatible(...)
```

B3 is not weakened. Every incompatible candidate in the deterministic stress cases is a physically present, representation-valid State candidate with the same candidate key used by cache-aware policies. The experiment does not obtain a result by withholding the exact candidate StateID from B3 or by giving B3 a malformed/nonexistent object.

# 2. Correctness separation

C4.3a makes three operations explicit:

```text
worker placement
    !=
State reuse decision
    !=
State consumption
```

Choosing a worker that once hosted or currently hosts State is not itself a WBRR/WSCR event.

The experiment maps the closed C3 abstractions to an explicit candidate-reuse action:

- B0 never consumes the candidate because State reuse is outside its information contract;
- B1/B2 consume the declared candidate only when placement selects a candidate-local worker under their candidate-key abstraction;
- B3 consumes the declared candidate only when placement selects a worker holding its exact StateID candidate;
- B4 consumes the candidate only when its placement decision is explicitly `COMPATIBLE_STATE_LOCALITY_THEN_LOAD`.

For B0–B3, C1 State lineage is not silently inserted as an extra policy-visible consumption guard. Doing so would give the non-lineage baselines the B4 mechanism under test. C1 remains the implementation semantic authority for B4's declared read-only compatibility query and is also checked against an independent experiment oracle.

# 3. Independent lineage oracle

The experiment oracle does not call either:

```text
ContinuityCore.is_ancestor(...)
ContinuityCore.state_compatible(...)
```

for its causal branch classification.

It independently traverses Continuation parent edges and verifies:

```text
State exists
State validity == VALID
origin Continuation exists
origin and consumer are in the same Session
origin Continuation is an ancestor of the consumer Continuation
```

C4.3a intentionally uses Continuation-origin State so the first slice isolates branch lineage from producer-Attempt and producer-Phase authority. Producer-authority pressure belongs in the adversarial C4.3b corpus.

For every trial, the harness separately requires C1 `state_compatible(...)` to agree with this independent oracle. A disagreement aborts the experiment rather than becoming policy evidence.

# 4. Deterministic scenarios

The canonical order is:

```text
FTR4
S2-ABANDONED-RESIDUE
S2-SIMILAR-DIFFERENT
S2-VALID-ANCESTOR
FTR5
```

## 4.1 FTR4 — wrong sibling State

```text
C0
├── C1 -> X-sibling @ w1
└── C2 -> consumer
```

`X-sibling` is physically/content-plausible but not an ancestor-compatible State for C2.

## 4.2 Abandoned-branch residue

A State produced under C1 remains physically valid on w1 after C1 becomes `ABANDONED`. A sibling C2 becomes active. Physical persistence must not reactivate the abandoned branch's causal authority.

## 4.3 Similar-but-different State

Two `PREFIX/KV` States share the same candidate-class surface:

```text
X-compatible     origin C0   @ w2
X-similar-wrong origin C1   @ w1
```

The consumer is sibling C2. The physically attractive candidate is `X-similar-wrong`; only lineage distinguishes it from the compatible alternative.

## 4.4 Valid ancestor control

```text
C0 -> X-ancestor @ w1
 |
 +-> C2 consumer
```

This is a non-faulted control. B4 must reuse compatible State when it is available; safety cannot be obtained merely by disabling all State reuse.

## 4.5 FTR5 — lost valid State

A valid ancestor State remains logically known, but its only replica becomes `LOST`. The consumer executes on a descendant Continuation. The safe behavior is recomputation/restore/failure, not invented State consumption.

The normalized C3 `PolicyObservation` contains one State-location tuple, so C4.3a does not pretend that FTR5 simultaneously represents a second unrelated candidate. Multi-candidate stale-cache/substitution pressure is deferred to C4.3b rather than encoded ambiguously.

# 5. Metric causality

## WBRR

Wrong-branch opportunities are fixed exogenous paired inputs before any policy executes.

C4.3a defines one WBRR EventID for each of:

```text
FTR4
S2-ABANDONED-RESIDUE
S2-SIMILAR-DIFFERENT
```

Every policy receives the same EventID for the same operation. A WBRR violation occurs only when that incompatible candidate is actually reused.

## WSCR

WSCR is policy-derived. A State-consumption EventID exists only when a policy actually consumes the candidate. An incompatible consumption is a WSCR violation.

A policy that safely recomputes has no fabricated WSCR denominator event.

## SSER / O-class

For faulted operations:

- incompatible State consumed and success committed -> O4;
- incompatible State rejected and work recomputed -> O2;
- lost valid State safely recomputed -> O2.

The valid-ancestor case has `fault_id=None`, no Gate opportunities, and is excluded from faulted O1–O4 denominators by the closed C4.1 summary contract.

# 6. Fairness and falsifiability

The State-local worker is deliberately busier than the alternative worker:

```text
w1  candidate-local, normalized load 1
w2  non-local, normalized load 0
```

This makes policy intent observable:

- B0 can choose the less-loaded worker without incidental reuse;
- B1/B2 may prefer candidate/session locality despite load;
- B3 may prefer exact-State locality despite load;
- B4 may prefer locality only after compatibility succeeds.

The experiment does not hard-code which policy must fail. It records the result produced by the closed policy implementation.

An anti-false-zero regression injects an incompatible candidate consumption into the measurement path and requires WBRR, WSCR, and O4 to become nonzero. This injection validates the evaluator; it is not part of the reported baseline result.

```text
validation level      EV0_DETERMINISTIC_SEMANTICS

```

Ground truth contains only policy-independent scenario facts and the independent compatibility oracle.

No hidden lineage field is made policy-visible to B0–B3.

1. the full repository test suite is green on Python 3.11, 3.12, and 3.13 on the exact candidate head;

The measured deterministic result and exact CI evidence will be appended only after those executions occur.
