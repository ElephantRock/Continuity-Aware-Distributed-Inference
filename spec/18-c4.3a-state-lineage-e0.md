# 1. Research boundary

C4.3a evaluates the deterministic State-lineage safety claim without changing C1, C2, C3, or the C4.1 correctness contract.

The canonical RQ2 question is whether causal State lineage prevents reuse of physically attractive but logically incompatible State.

Primary S2 correctness metrics in this slice are:

```text
WBRR
WSCR
SSER
```

The closed C3 baseline distinction is preserved exactly:

```text
B0  request/load only
B1  candidate-key cache locality
B2  session affinity + candidate locality
B3  exact StateID + precise State location, causally blind
B4  complete Continuity context + C1 state_compatible(...)
```

C4.3a does not reinterpret the C3 return type. C3 returns `PlacementDecision`; it does not return a State reuse or State consumption decision.

That distinction is a mandatory measurement boundary in this record.

---

# 2. Placement, execution, and consumption are separate

The experiment explicitly separates:

```text
policy placement
    !=
worker execution rule
    !=
State consumption event
```

A worker choice is never itself counted as State reuse or State consumption.

The initial C4.3a implementation incorrectly inferred consumption from B1/B2/B3 selecting a State-local worker. Exact-head review rejected that inference because C3 exposes placement only and B2 can select the same worker solely because of session affinity.

That measurement path was removed.

## 2.1 Exogenous execution directive

Every policy now receives the same policy-independent worker execution contract:

```text
CONSUME_DECLARED_CANDIDATE_IF_VALID_REPLICA_IS_LOCAL
```

For each scenario, ground truth contains a `StateConsumptionDirective` identifying the declared candidate State and this fixed rule.

After C3 placement, the common execution function checks only physical execution facts:

```text
selected worker exists
candidate replica exists
replica StateID matches the declared candidate
replica status == VALID
replica location == selected worker
```

Only when all conditions hold does the worker runtime emit a concrete `StateConsumptionEvent` containing:

```text
event_id
directive_id
state_id
replica_id
worker_id
```

The execution function intentionally has no `PolicyID` input and does not inspect `PlacementDecision.reason`.

Therefore:

- B2 session affinity by itself does not count as consumption;
- a LOST local replica does not count as consumption even if B2 selects that worker;
- the same selected worker and physical replica produce the same consumption event regardless of which policy selected the worker;
- policy decision records contain placement only, while the consumption event is recorded under observed execution evidence.

This is an end-to-end experiment contract over a common worker runtime. It is not a claim that the closed C3 placement interface itself performs State consumption.

# 3. Independent semantic oracle

The experiment oracle does not call either:

```text
ContinuityCore.is_ancestor(...)
ContinuityCore.state_compatible(...)
```

for ground-truth compatibility classification.

It independently checks the covered C4.3a semantic dimensions:

```text
ExecutionContext object/link consistency
consumer Attempt is CURRENT
State exists
State validity == VALID
origin Continuation exists
origin and consumer share the Session
origin Continuation is an ancestor of the consumer Continuation
producer Attempt exists when declared
producer Attempt is not SUPERSEDED
completed producer Request committed that producer Attempt
```

C4.3a deliberately excludes Phase-origin and derived-State dependency pressure; those dimensions belong in the adversarial C4.3b corpus.

For every trial, the harness separately evaluates C1 `state_compatible(...)` and requires it to agree with the independent oracle. A disagreement aborts the experiment rather than becoming policy evidence.

# 4. Deterministic scenarios

Canonical C4.3a order is:

```text
FTR4
FTR5
FTR14
S2-SIMILAR-DIFFERENT
S2-VALID-ANCESTOR
FTR6
```

## 4.1 FTR4 — wrong sibling State

```text
C0
├── C1 -> X-sibling @ w1
└── C2 -> consumer
```

`X-sibling` is physically valid and candidate-plausible but is not ancestor-compatible with C2.

This is a WBRR opportunity and, if an actual consumption event occurs, a WSCR opportunity.

## 4.2 FTR5 — superseded-producer State

Canonical failure-model meaning:

```text
C1 / Rp
├── A1 -> X1 @ w1
└── A2 commits

A1 = SUPERSEDED
```

The State is created while A1 is still current and remains physically VALID on w1 after A2 supersedes and commits. A later descendant request is then placed.

Expected semantic rule:

```text
X1 rejected for later cross-request reuse
```

FTR5 is State-consumption pressure but is not a wrong-branch event, so it contributes WSCR when consumed but not WBRR.

## 4.3 FTR14 — abandoned-branch residual State

A State produced under C1 remains physically VALID on w1 after C1 becomes `ABANDONED`. A sibling C2 becomes active.

Physical persistence must not reactivate abandoned causal authority.

This is a WBRR opportunity and, if consumed, a WSCR opportunity.

## 4.4 S2-SIMILAR-DIFFERENT

Two `PREFIX/KV` States are structurally similar:

```text
X-compatible     origin C0   @ w2
X-similar-wrong origin C1   @ w1
```

The consumer is sibling C2. The declared candidate is the physically attractive wrong State at w1.

Only causal lineage distinguishes it from a compatible State of the same semantic/representation class.

This is a WBRR opportunity and, if consumed, a WSCR opportunity.

## 4.5 S2-VALID-ANCESTOR control

```text
C0 -> X-ancestor @ w1
 |
 +-> C2 consumer
```

This is non-faulted. B4 must still reuse compatible local State when available; safety cannot be obtained by disabling reuse globally.

The control carries no Gate G1 opportunity and does not enter faulted SSER denominators.

## 4.6 FTR6 — lost valid State

A logically compatible ancestor State exists, but its only physical replica transitions to `LOST`.

Expected behavior:

```text
recompute / repair / fail
not substitute unrelated State
```

The policy-visible State location tuple is empty after loss. The physical replica object remains in ground truth with status `LOST` so the execution rule can prove that worker selection alone does not create consumption.

# 5. Fairness boundary

Every incompatible candidate used for comparator pressure is:

```text
real C1 State identity
StateValidity.VALID
PREFIX / KV representation
physically resident as a VALID replica on w1
candidate-key plausible
```

B3 receives the exact candidate StateID and location exactly as its closed C3 information contract permits.

No C1 causal ancestry or producer-authority result is silently added to B0-B3.

The worker layout is deliberately:

```text
w1  candidate-local, normalized load 1
w2  non-local, normalized load 0
```

This makes placement intent observable:

- B0 naturally prefers w2 by load;
- B1 can prefer w1 by candidate locality;
- B2 can prefer w1 by candidate locality and/or session affinity;
- B3 can prefer w1 by exact-State locality;
- B4 prefers w1 only after C1 compatibility succeeds, otherwise it falls back to load.

The common worker execution rule is then applied identically after placement.

No baseline is weakened and no B0-B3 correctness guard is disabled relative to the declared baseline abstraction.

# 6. Metric causality

## 6.1 WBRR

WBRR opportunities are fixed exogenous paired events for exactly:

```text
FTR4
FTR14
S2-SIMILAR-DIFFERENT
```

Each policy receives the same EventID for the same scenario.

A WBRR violation occurs only if the explicit worker-runtime `StateConsumptionEvent` consumes the incompatible branch candidate.

Placement alone never increments WBRR.

## 6.2 WSCR

WSCR is policy-derived under the closed C4.1 metric-scope contract.

A WSCR denominator event exists only when the worker runtime actually emits a `StateConsumptionEvent` during a faulted operation.

An incompatible consumption increments the WSCR numerator.

A policy that recomputes without a consumption event has no fabricated WSCR denominator.

## 6.3 SSER / O-class

For faulted operations:

- explicit incompatible State consumption followed by committed success -> O4;
- incompatible State avoided and work recomputed -> O2;
- lost State not consumed and work recomputed -> O2.

The valid-ancestor control is non-faulted and excluded from the faulted O1-O4/SSER denominator by C4.1.

# 7. Anti-false-zero and measurement-integrity regressions

C4.3a now includes regressions proving:

1. the post-placement execution function has no policy-specific branch;
2. two synthetic placement decisions from different policies selecting the same valid local replica produce the same consumption event;
3. selecting a non-local worker produces no consumption event;
4. selecting the original worker after replica status becomes `LOST` produces no consumption event;
5. B2 session affinity may still select w1 under FTR6 without creating a false consumption;
6. actual consumption events, not placement decisions, create WSCR denominators;
7. an injected incompatible consumption event increments WBRR/WSCR and produces O4, preventing a false-zero evaluator;
8. the independent oracle and C1 compatibility result agree for every reported trial;
9. FTR5 ground truth explicitly records A1 as `SUPERSEDED` and A2 as the committed producer Request Attempt.

The injected event is evaluator validation only and is excluded from the reported baseline result.
