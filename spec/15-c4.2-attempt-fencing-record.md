# 4. Critical S1 boundary

The governing rule is:

> **placement admission is not authoritative result acceptance.**

C3 policy behavior and C1 semantic authority are therefore recorded as separate surfaces.

For a stale Attempt:

- B0–B3 may still return a worker placement because their closed information contracts do not include Attempt authority;
- B4 may return `ATTEMPT_FENCED` because its closed C3 contract can inspect Attempt identity/authority and read-only C1 current-Attempt status;
- neither outcome is itself a SAAR numerator event.

SAAR remains:

```text
stale Attempt results accepted authoritatively
---------------------------------------------
stale Attempt results presented
```

Authoritative acceptance is determined from the shared C1 finalization path, not from whether a policy admitted or rejected physical work.

This prevents a B4 placement distinction from being silently relabeled as semantic correctness.

For the late-superseded-Attempt traces FTR1 and FTR3, the harness validates the Experimental Plan's injector obligations at runtime.

At supersession:

```text
A1 execution == RUNNING
A1 authority == SUPERSEDED
```

```text
delivery_time > supersession_time
A1 execution == SUCCEEDED

```

Thus the denominator event is not inferred merely from an event label. The runtime semantic state independently confirms that the delivered A1 result is stale.

# 6. Metric construction

## 6.1 SAAR

Each validated `LATE_RESULT` for a superseded Attempt contributes one exogenous paired opportunity event:

```text
metric  STALE_ATTEMPT_ACCEPTANCE_RATE
scope   EXOGENOUS_PAIRED
event   exact scenario EventID
```

A violation is recorded only if the final authoritative LogicalRequest commit selects one of those stale Attempt IDs.

## 6.2 DFR

Each completed LogicalRequest contributes one policy-derived opportunity event:

```text
metric  DUPLICATE_FINALIZATION_RATE
scope   POLICY_DERIVED
event   completed-request:<LogicalRequestID>
```

A violation is recorded if the semantic adapter reports more than one `APPLIED` `finalize_request` transition for that completed LogicalRequest. Idempotent duplicate delivery does not count as duplicate semantic finalization.

## 6.3 SSER

SSER remains the C4.1 operation-level O4 ratio. The expected authoritative Attempt for each deterministic trace is part of independent experiment ground truth:

```text
FTR1 -> A2
FTR2 -> A1
FTR3 -> A2
```

An unexpected authoritative winner becomes O4; an expected winner remains O1/O2 depending on whether retry recovery occurred.

# 7. Policy-decision diagnostic

At each stale result presentation, C4.2a records a diagnostic stale-Attempt admission decision using the closed C3 policy interface and one neutral available worker.

The diagnostic is explicitly serialized with:

```text
stale_attempt_admission_probe_is_gate_metric = false
semantic_authority = C1_COMMON_TO_B0_B4
```

Its purpose is to expose the causal distinction between:

```text
B4 stale-work admission fencing
```

and:

```text
C1 authoritative finalization fencing
```

without coupling the former to SAAR.

# 8. Fairness / null-result rule

C1 is semantic authority for the closed C1/C2/C3 stack. C4.2a does not selectively remove C1 idempotence or semantic commit guards from B0–B3.

Therefore the deterministic S1 result may legitimately be:

```text
B0 SAAR = 0
B1 SAAR = 0
B2 SAAR = 0
B3 SAAR = 0
B4 SAAR = 0
```

while B4 alone fences stale placement.

If exact-head execution confirms that pattern, it is a deterministic null comparator result for H1 criterion 4. It must be recorded as such. It must not be converted into a B4 correctness win by counting placement admission as authoritative acceptance or by weakening competent baselines.

H1 can still remain an implementation property, but its independent novelty claim must be narrowed unless later C4.2b/C4.2c evidence provides a defensible comparator distinction without changing baseline semantics.
