# 4. Critical S1 boundary

The governing rule is:

> **placement admission is not authoritative result acceptance.**

C3 policy behavior and C1 semantic authority are therefore recorded as separate surfaces.

For a stale Attempt:

- B0–B3 may still return a worker placement because their closed information contracts do not include Attempt authority;
- B4 may return `ATTEMPT_FENCED` because its closed C3 contract can inspect Attempt identity/authority and read-only C1 current-Attempt status;
- neither outcome is itself a SAAR numerator or denominator event.

SAAR remains:

```text
stale Attempt results accepted authoritatively
---------------------------------------------
stale Attempt results presented for authoritative acceptance
```

A physical `LATE_RESULT` completion is not, by itself, an authoritative presentation. A SAAR opportunity exists only when a stale terminal observation reaches the shared C1 finalization path.

This prevents either physical completion or B4 placement fencing from being silently relabeled as semantic correctness.

# 5. Fault-ground-truth validation

For FTR1 and FTR3, the harness validates the late-superseded-Attempt fault condition independently of SAAR counting.

At supersession:

```text
A1 execution == RUNNING
A1 authority == SUPERSEDED
A2 authority == CURRENT
LogicalRequest.current_attempt_id == A2
```

At physical late completion:

```text
delivery_time > supersession_time
A1 execution == SUCCEEDED
A1 authority == SUPERSEDED
```

These checks prove that the physical late-result hazard is real. They do not create the SAAR denominator.

At stale authority presentation:

```text
A1 execution == SUCCEEDED
A1 authority == SUPERSEDED
terminal observation reaches finalize_request
```

The post-event authoritative request state records whether A1 was accepted.

# 6. SAAR opportunity manifest

SAAR opportunities are exogenous paired events and are fixed before policy execution.

## FTR3

FTR3 already contains a canonical stale A1 terminal observation after A2 commits. That `OBSERVATION_CREATED` event is the SAAR opportunity.

## FTR1

FTR1 contains a physical stale A1 late completion but no subsequent stale A1 terminal observation. C4.2a therefore adds one deterministic **C4-only supplemental presentation** after the canonical scenario finishes its late physical completion:

```text
event_id  c4.2a:FTR1:stale-authority-presentation:a1
source    C4_SUPPLEMENTAL_PRESENTATION
```

The supplemental event is scheduled through the existing `ContinuityAdapter`. It does not modify the closed C2 scenario catalogue or C1 semantics. Its identity, AttemptID, RequestID, EvidenceID, OutputID, and delivery time are recorded in independent experiment ground truth and are identical for B0–B4.

Thus the deterministic S1 SAAR cohort contains exactly two authority-presentation opportunities:

```text
FTR1  one supplemental stale A1 finalization attempt
FTR3  one canonical stale A1 finalization attempt
```

Physical `LATE_RESULT` EventIDs are recorded separately and never reused as SAAR opportunity IDs.

# 7. Metric construction

## 7.1 SAAR

Each stale terminal authority presentation contributes:

```text
metric  STALE_ATTEMPT_ACCEPTANCE_RATE
scope   EXOGENOUS_PAIRED
event   exact stale-observation EventID
```

Every SAAR opportunity must have a matching `finalize_request` action record. A violation is recorded only if the post-presentation authoritative request state selects the stale Attempt.

## 7.2 DFR

Each completed LogicalRequest contributes one policy-derived opportunity event:

```text
metric  DUPLICATE_FINALIZATION_RATE
scope   POLICY_DERIVED
event   completed-request:<LogicalRequestID>
```

A violation is recorded if the semantic adapter reports more than one `APPLIED` `finalize_request` transition for that completed LogicalRequest. Idempotent duplicate delivery does not count as duplicate semantic finalization.

## 7.3 SSER

SSER remains the C4.1 operation-level O4 ratio. Independent experiment ground truth fixes the expected authoritative Attempt:

```text
FTR1 -> A2
FTR2 -> A1
FTR3 -> A2
```

An unexpected authoritative winner becomes O4; an expected winner remains O1/O2 depending on retry recovery.

# 10. Bounded-review finding repaired

The first C4.2a candidate incorrectly counted physical `LATE_RESULT` events as SAAR denominator events. That made FTR1 report a guaranteed `0/1` even though no stale A1 terminal observation ever attempted authoritative finalization, and it used the physical-completion event instead of FTR3's later stale A1 observation.

Repair:

1. physical late completion now validates fault ground truth only;
2. SAAR opportunities are terminal stale observations that each reach `finalize_request`;
3. FTR3 uses its canonical stale A1 observation;
4. FTR1 receives one deterministic C4-only stale terminal observation after its canonical late completion;
5. regression coverage requires every SAAR opportunity EventID to appear in a finalization action record and forbids physical `LATE_RESULT` IDs from serving as SAAR opportunities.
