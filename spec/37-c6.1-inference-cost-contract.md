# C6.1 — Inference-Cost Contract and Provenance Schema

## Status

First bounded C6 slice under issue #103 / umbrella #102.

Base main:

```text
80b1051c5545f4bfc62047714c8687ae9aaed86a
```

C6.1 defines EV3 inference-cost mechanics and parameter provenance. It does **not** establish a physical calibration or an H4/H5/H7 efficiency result.

## Research boundary

The C6 roadmap requires modeled outputs for:

```text
prefill cost
decode cost
recompute cost
transfer cost
memory footprint
```

and requires every physical-performance parameter to be traceable to published/validated evidence, direct measurement where appropriate, or an explicitly synthetic sensitivity range. No unexplained constants are admissible.

C6.1 therefore separates two concerns:

```text
cost-model mechanics
        !=
physical calibration
```

The mechanics are fixed here. C6.2 supplies defensible published/validated calibration profiles.

## Parameter source classes

`ParameterSourceClass` is restricted to:

```text
PUBLISHED_OR_VALIDATED_PROFILE   # P-SRC2
DIRECT_CPU_MEASUREMENT           # P-SRC3
SYNTHETIC_SENSITIVITY            # P-SRC4
```

C5 P-SRC1 public-trace fields remain workload inputs, not physical calibration parameters.

Every numeric parameter is wrapped in `SourcedScalar` with:

```text
value
unit
ParameterProvenance
optional sensitivity range
```

`ParameterProvenance` contains:

```text
source class
nonempty reference
optional note
```

Synthetic parameters are rejected unless they carry a non-degenerate sensitivity range containing the nominal value. This prevents a convenient synthetic point value from being presented as a calibrated physical constant.

## Profile contract

`InferenceCostProfile` records:

```text
profile_id
model_id
hardware_id
representation_id

prefill_fixed_seconds
prefill_seconds_per_input_token

decode_fixed_seconds
decode_seconds_per_context_token_step

state_fixed_bytes
state_bytes_per_token
memory_capacity_bytes

transfer_bandwidth_bytes_per_second
transfer_latency_seconds

optional ModelValidation
```

All fields have explicit canonical units. Memory capacity and transfer bandwidth must be strictly positive. Other coefficients must be finite and nonnegative.

The profile has canonical JSON and a SHA-256 fingerprint. Any change to a serialized parameter, provenance record, identity, or validation record changes the fingerprint.

## Workload contract

`InferenceCostWorkload` records only explicit nonnegative integer work quantities:

```text
input_tokens
output_tokens
reusable_prefix_tokens
state_tokens
```

and requires:

```text
reusable_prefix_tokens <= input_tokens
```

No implicit assumption equates source-trace fields with physical calibration.

## Transparent C6.1 mechanics

The C6.1 evaluator intentionally uses simple explicit mechanics whose coefficients are supplied entirely by the profile.

### Prefill

For positive input length:

```text
prefill_seconds =
    prefill_fixed_seconds
    + prefill_seconds_per_input_token * input_tokens
```

For zero input tokens, prefill cost is zero.

### Decode

Decode work is represented as context-token steps:

```text
decode_context_token_steps =
    output_tokens * input_tokens
    + output_tokens * (output_tokens - 1) / 2
```

For positive output length:

```text
decode_seconds =
    decode_fixed_seconds
    + decode_seconds_per_context_token_step
      * decode_context_token_steps
```

For zero output tokens, decode cost is zero.

This is an explicit C6.1 mechanics contract, not a claim that one linear coefficient is sufficient for every engine or hardware profile. If C6.2 reference evidence requires a richer validated functional form, that change must be explicit and source-justified rather than hidden in coefficients.

### Recompute

Missing reusable prefix work is explicit:

```text
recompute_tokens = input_tokens - reusable_prefix_tokens
```

If `recompute_tokens == 0`, recompute cost is zero. Otherwise recompute uses the same prefill mechanics over the missing prefix work:

```text
recompute_seconds =
    prefill_fixed_seconds
    + prefill_seconds_per_input_token * recompute_tokens
```

No independent recomputation magic constant exists.

### State memory

```text
state_bytes =
    state_fixed_bytes
    + state_bytes_per_token * state_tokens

memory_capacity_fraction =
    state_bytes / memory_capacity_bytes
```

A fraction above one is a modeled capacity violation signal, not silently clamped.

### Transfer

C6.1 uses the same transparent latency-plus-serialization structure as the existing C2 `NetworkLink` model:

```text
transfer_seconds =
    transfer_latency_seconds
    + state_bytes / transfer_bandwidth_bytes_per_second
```

The bandwidth and latency are sourced profile parameters; they are not embedded constants.

## Validation record

`ModelValidation` is optional in C6.1 and records:

```text
metric
error_value
unit
reference
```

C6.3 must populate and adjudicate validation error for profiles intended to support C7 headline efficiency results.

## Deterministic fixture policy

Unit tests use a bounded `SYNTHETIC_SENSITIVITY` profile only to validate:

```text
source-tag enforcement
synthetic-range enforcement
unit enforcement
canonical serialization/fingerprinting
deterministic cost arithmetic
explicit recomputation composition
invalid-domain rejection
```

Those fixture values are not calibrated, representative, or admissible as hardware evidence.

## C6.1 exit criterion

C6.1 passes when:

```text
all numeric profile parameters are source-tagged
synthetic point values cannot omit sensitivity ranges
canonical units are enforced
profile fingerprint is deterministic and drift-sensitive
prefill/decode/recompute/transfer/memory outputs are deterministic
invalid/non-finite domains fail closed
no physical calibration or efficiency claim is promoted from fixture values
all tests/CI green
bounded technical/scientific review passes
```

After C6.1, C6.2 selects and implements the first defensible published/validated calibration source(s).
