---

# 1. Why C1 is being reopened

C4.5a measured a real conflict between the closed C1 reconciliation semantics and the closed C1 semantic-commit path.

For the same supplied Evidence set:

```text
E1  EXACT_OBSERVATION / VALID     / attempt a1
E2  EXACT_OBSERVATION / AMBIGUOUS / attempt a1
```

closed C1 produced:

```text
reconcile(finalize, {E1,E2}) = AMBIGUOUS
finalize_request(...)         = APPLIED
```

The pre-repair experiment records:

```text
ACR  = 1/9
SSER = 1/9
O4   = 1 faulted operation
```

for every B0–B4 policy because all policies share the same C1 finalization authority.

This is not rewritten as an experiment bug or baseline difference. It is an explicit C1 safety defect discovered by C4.

---

# 2. Canonical obligation

The governing safety rule is:

```text
correctness-sensitive semantic commit
=> sufficient Evidence and no unresolved ambiguity
```

The repair applies to the current Paper-1 correctness-sensitive Evidence actions:

```text
finalize
consume_state
commit_migration
```

Performance-only Evidence actions remain outside this new fail-closed obligation.

---

# 3. Repair semantics

The repair centralizes enforcement in `require_evidence(...)`.

For a correctness-sensitive action:

```text
if any supplied Evidence item has status AMBIGUOUS:
    raise InsufficientEvidence
```

Only after that guard passes does the existing authority/status/freshness/scope sufficiency scan run.

This intentionally matches the already-closed `reconcile(...)` semantics, which classify the supplied set as `AMBIGUOUS` if any supplied Evidence item is explicitly ambiguous.

The repair does **not** change set-level ambiguity into scope-filtered ambiguity. That is a separate semantic question and is unnecessary to repair the measured same-scope defect.

---

# 4. API compatibility

No new public exception type is introduced.

Existing action behavior remains:

```text
finalize_request  -> InsufficientEvidence; no authoritative finalization
can_consume_state -> False through existing InsufficientEvidence handling
commit_migration  -> InsufficientEvidence; no Binding transition
reconcile         -> AMBIGUOUS
```

Performance actions such as `rank_endpoint` retain their existing degradable `require_evidence(...)` behavior even when an ambiguous item is supplied alongside an otherwise sufficient item.

---

# 5. Regression obligations

The repair test suite must prove:

```text
mixed valid+ambiguous finalize        fails closed
mixed valid+ambiguous consume_state   fails closed
mixed valid+ambiguous commit_migration fails closed
reconcile(mixed set) remains AMBIGUOUS
valid-only finalization still succeeds
performance Evidence requirement retains existing behavior
```

No test or implementation change may delete, rewrite, or retroactively pass the preserved pre-repair PR #71 evidence.

---

# 6. Post-repair requirement

This repair does not itself close C4.5a.

After independent merge, the deterministic S4 corpus must be reproduced from repaired `main`. The mandatory mixed case must then produce:

```text
reconciliation          = AMBIGUOUS
authoritative finalization = rejected
ACR                      = 0
O4                       = 0
```

The post-repair run must use the same independent oracle and denominator contract as the pre-repair measurement.

---

# 7. Scientific interpretation

The research record must preserve both facts:

1. the original closed C1 stack failed the S4 ambiguity invariant; and
2. the defect was repaired explicitly before C4.5 continued.

The repair therefore strengthens artifact correctness but cannot be cited as evidence that the original C1 implementation was already correct.
