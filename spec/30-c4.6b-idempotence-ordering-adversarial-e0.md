# C4.6b — Adversarial S5 Duplicate / Reordering Permutation EV0

Status: candidate implementation for issue #86 under C4.6/S5 #83.

Base milestone: `6900c23c5ce8188e0e910be931c45f55c957bb7c` (C4.6a closure).

## Purpose

This slice evaluates S5 under a bounded, predeclared duplicate/reordering corpus. It does not alter C1/C2/C3. The required metamorphic property is:

```text
canonical authoritative snapshot
== every permitted duplicate/reordering variant authoritative snapshot
```

Observation delivery order itself is not authority. Raw event-order logs may differ while normalized semantic state remains equivalent.

## Independent oracle

Each permutation family has a declaratively specified normalized target snapshot. The canonical trace is executed and must first match that independent target. Every adversarial variant then runs from a fresh runtime and is compared to the same target. The oracle therefore does not ask the implementation whether it considers itself idempotent.

## Frozen families

The 14 variants were predeclared in issue #86 before implementation.

### P1 duplicate finalization

Canonical `F U`; variants `F F U`, `F U F`, `U F F`.

Target: request r1 COMPLETED by a1, authoritative output o1, a1 COMMITTED, one independently observed finalization effect.

### P2 conflicting output

Canonical `F1 U`; variants `F1 F2 U`, `F1 U F2`, `U F1 F2`.

Target: r1 remains COMPLETED by a1 with immutable o1; o2 is never authoritative.

### P3 Attempt-generation ordering

A1 is successful but SUPERSEDED by starting A2 before deliveries are applied. Canonical `NEW U`; variants `OLD NEW U`, `NEW OLD U`, `U OLD NEW`.

Target: r1 COMPLETED by a2 with o2; a1 SUPERSEDED; a2 COMMITTED. OLD is allowed to reject differently depending on whether NEW has already completed the request, but cannot gain authority.

### P4 duplicate EventID

Canonical `E U`; variants `E E U`, `E U E`, `U E E`.

Target: exactly one primary event-1 with its original payload and one unrelated event-u. Raw event_order is deliberately excluded from the semantic oracle; identity/payload set is normalized and compared.

### P5 stale Binding loser

B2 and B3 are proposed from the same base epoch. Canonical `WIN U`; variants `WIN LATE U`, `WIN U LATE`.

Target: B2 remains current ACTIVE Binding at epoch 2; B1 SUPERSEDED; B3 remains non-authoritative MIGRATING at epoch 3. LATE may reject but cannot change semantic ownership.

## DFR denominator semantics

DFR remains `POLICY_DERIVED`.

The harness creates a DFR opportunity only when the observed post-trace state contains an actually COMPLETED LogicalRequest with a committed Attempt and authoritative output. No request completion means no DFR opportunity. Thus P4/P5 remain null-denominator operations. If all request-family variants complete as intended, the per-policy aggregate denominator is nine.

Opportunity identity is derived from the concrete completion:

```text
S5:ADV:<variant>:completed-request:<request-id>
```

## Finalization accounting

Request traces reuse the independent before/after authoritative Request snapshot accounting established in C4.6a. A semantic finalization effect is counted when a trace transitions into a completed authoritative output or changes that authoritative output. The runtime method's return value is not the DFR oracle.

The private P1 anti-false-zero path executes the real permutation first, then injects a second authoritative-output transition. It must create both a snapshot mismatch and a DFR violation and classify O4.

## Baseline fairness

All B0-B4 execute the same permutation manifest against common C1 semantic machinery. No baseline loses request immutability, Attempt fencing, EventID deduplication, Binding epochs, or other ordinary correctness mechanisms. No policy-specific S5 information surface is introduced.

A semantic null comparator is therefore acceptable and expected if the common mechanism is sufficient.
