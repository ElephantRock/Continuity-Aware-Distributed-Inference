## 1. Scope

C8.2 implements the smallest real process/socket substrate needed by C8.3. It is mechanics/conformance evidence only. It does not adjudicate C4 correctness on C8 traces and does not produce Gate G3 timing evidence.

## 2. Physical topology

Reference topology:

```text
CONTROL_PLANE_AUTHORITY process
    ^
    | canonical framed TCP over AF_INET loopback
    v
FAULT_TRANSPORT_HARNESS process
    ^
    | canonical framed TCP over AF_INET loopback
    v
WORKER process
```

Every role obtains its PID from `os.getpid()` inside that process. The authority learns worker/harness PID claims only through serialized registration messages. The parent test/orchestrator may observe `multiprocessing.Process.pid` as a cross-check, but it is not the source used in the process event log.

Only `prototype/c8_authority.py` imports and instantiates `ContinuityCore`. Worker and harness modules intentionally do not import `continuity`.

## 3. Strict wire format

`prototype/c8_transport.py` implements the C8.1 reference framing:

```text
4-byte unsigned big-endian payload length
canonical UTF-8 JSON payload
```

The decoder rejects:

- zero or oversized length;
- truncated header or payload;
- invalid UTF-8;
- invalid JSON;
- NaN/Infinity;
- valid but non-canonical JSON;
- missing or extra envelope fields;
- unsupported message schema/kind/role;
- invalid monotonic timestamp representation.

Reference traffic never uses pickle or direct Python-object message passing.

## 4. Message kinds

C8.2 defines only physical/substrate kinds:

```text
REGISTER
REGISTERED
WORK
COMPLETE
PROCESS_FAILURE
SHUTDOWN
SHUTDOWN_ACK
```

The synthetic `WORK` command is deterministic SHA-256 work used only to prove real process execution and completion transport. It is not inference timing and it is not a Continuity semantic operation.

## 5. Authority behavior

The authority process owns one `ContinuityCore` instance but C8.2 does not yet map synthetic completions into C1 semantic mutations. That mapping belongs to C8.3.

The authority:

1. accepts one external harness TCP connection;
2. validates harness registration;
3. validates worker registration relayed by the harness;
4. rejects a worker registration if the worker reports any loaded `continuity` module;
5. dispatches deterministic synthetic work;
6. records physical completion as an observation;
7. optionally sends graceful worker shutdown;
8. records real harness-reported process failure explicitly as non-semantic observation.

`send_monotonic_ns` is logged but never consulted for authority decisions.

## 6. Worker behavior

The worker is a separate OS process that:

- connects only to the harness endpoint;
- self-reports its PID;
- reports whether any `continuity` module was loaded;
- executes deterministic synthetic SHA-256 work;
- emits a serialized completion;
- supports graceful shutdown and acknowledgement.

A worker has no path to a mutable `ContinuityCore` object.

## 7. External fault harness

The harness is a separate OS process between authority and worker. It validates and re-encodes canonical envelopes rather than forwarding arbitrary Python objects.

A deterministic bounded `DeliveryScheduler` supports:

```text
DELIVER
DELAY
DUPLICATE
REORDER
DROP
LATE_DELIVER
```

`DELAY` and `LATE_DELIVER` retain already-encoded frames in bounded queues. `REORDER` holds one frame and emits the second before the first. `DROP` is explicit. Queue capacity exhaustion produces an explicit `QUEUE_CAPACITY_FAILURE` event rather than unbounded growth or indefinite blocking.

The harness never changes semantic subject identifiers or grants semantic authority.

## 8. Real lifecycle behavior

`prototype/c8_runtime.py` uses the `spawn` multiprocessing context. It launches real authority/harness/worker processes and manages process termination/restart only as test orchestration.

A forced worker termination closes the real worker TCP socket. The harness converts that transport observation into a serialized `PROCESS_FAILURE` observation for the authority. Restart creates a new OS process and therefore new self-reported PID.

Graceful worker shutdown uses serialized `SHUTDOWN` / `SHUTDOWN_ACK` messages.

## 9. Canonical per-process event logs

Each role writes its own canonical JSONL event log. Events contain at minimum:

```text
schema
event_index
process_role
pid
message_id
message_kind
subject_type
subject_id
action
result
monotonic_ns
details
```

The index and timestamp are experiment bookkeeping only and have no semantic authority. Per-process logs avoid unsynchronized multi-process writes to one file and are suitable for C8.3 reconciliation.

## 10. Runtime git provenance helper

`resolve_clean_checkout()` derives `git rev-parse HEAD` from the executing checkout and rejects tracked or non-ignored untracked changes using:

```text
git status --porcelain --untracked-files=all
```

C8.2 tests this helper in a disposable git repository. No headline EV1 measurement is produced.

## 11. Conformance tests

`tests/prototype/test_c8_substrate.py` verifies:

- C8.1 fingerprint remains frozen;
- strict canonical frame round-trip;
- rejection of malformed/noncanonical/truncated/oversized/extra-field/non-finite frames;
- deterministic behavior for all six fault actions;
- explicit bounded queue failure;
- worker/harness source modules do not import `continuity`;
- real authority/harness/worker processes have distinct self-reported PIDs;
- self-reported PIDs agree with independent parent process handles;
- traffic crosses the harness over actual loopback TCP;
- physical completion does not consult message timestamps for authority;
- graceful worker shutdown succeeds;
- forced worker termination is observed and restart produces a new PID;
- actual duplicated completion delivery preserves the same transport message identity;
- clean-checkout provenance rejects tracked and untracked drift.
