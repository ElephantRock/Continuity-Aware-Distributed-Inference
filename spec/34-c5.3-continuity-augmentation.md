# C5.3 — Synthetic Continuity augmentation with explicit provenance

## Status

Candidate implementation for issue #96 under C5 umbrella #90.

Base:

```text
C5.2 merge
7b62908d94f7284f38039b7c896760caa79a2794
```

C5.3 adds a reproducible synthetic Continuity overlay to a normalized public-trace dataset. It does not change source-observed or trace-derived workload facts and it does not execute simulator faults.

## Layer boundary

C5.3 keeps two artifacts separate:

```text
NormalizedTraceDataset
  source-observed + mechanically TRACE_DERIVED workload facts

ContinuityAugmentationDataset
  SYNTHETIC Session / Continuation / tool-wait / branch / fault annotations
```

The augmentation stores only source `record_id` linkage plus synthetic fields. It binds the exact normalized source artifact through `source_dataset_fingerprint` and does not copy arrival time, token lengths, prefix group, or prefix-token values.

The input source dataset is serialized before and after augmentation in deterministic tests to confirm byte-identical immutability.

## Provenance

Every augmentation artifact records:

```text
schema
  cadi.c5.3.continuity-augmentation.v1

augmentation_version
  cadi.c5.3.synthetic-continuity.v1

provenance
  SYNTHETIC

source_dataset_fingerprint
  SHA-256 of canonical C5.1 normalized source JSON

config
  complete explicit synthetic configuration

annotations
  exactly ordered source-linked synthetic annotations
```

No synthetic field is relabeled as `SOURCE_OBSERVED` or `TRACE_DERIVED`.

## Configuration

The explicit configuration contains:

```text
seed
session_length_records

tool_wait_probability
tool_wait_seconds

branch_probability
branch_lookback_records

fault_probability
fault_classes
```

Rules:

- `seed` is a nonnegative integer;
- `session_length_records` is positive;
- probabilities are finite values in `[0,1]`;
- tool-wait choices are unique finite positive durations;
- nonzero tool-wait probability requires at least one duration choice;
- branch lookback is at least two records;
- nonzero branch probability requires a session long enough to admit that lookback;
- fault classes are unique members of the existing policy-neutral C2 `FaultClass` catalogue;
- nonzero fault probability requires at least one configured fault class.

The dataset constructor additionally rejects a serialized tool-wait value or fault annotation that is not present in the explicit configuration. Reproduction checks provide the stronger oracle that the complete annotation stream was actually generated by the recorded source/config/seed tuple.

No configuration is described as representative or realistic by construction. Later C5/C7 sensitivity work must vary synthetic assumptions.

## Deterministic decision construction

C5.3 does not use process-global RNG state or Python's `random` implementation.

Each decision channel uses SHA-256 over the UTF-8 encoding of:

```text
seed
source_dataset_fingerprint
record_id
channel
```

joined by the unit-separator byte. The first eight digest bytes define a deterministic draw in `[0,1)`; bytes 8–15 define deterministic choice indices.

Decision channels are separated for:

```text
branch
tool-wait
tool-wait-choice
fault
fault-class
```

A frozen deterministic fixture records the exact normalized-source fingerprint, generated annotations, and augmentation fingerprint, providing a cross-supported-Python replay vector.

## Session and Continuation construction

Source-order records are partitioned into fixed-size synthetic Sessions.

For source-order position `p`:

```text
session_index = p // session_length_records
local_index   = p % session_length_records
```

IDs are deterministic position-derived strings.

The first record in each Session is a root Continuation with no parent, no branch group, and no tool wait. Normally each later Continuation extends the immediately preceding Continuation.

When branching fires and sufficient same-Session history exists, the parent becomes the configured lookback ancestor and a synthetic branch-group identifier records the fork point. Parent links must precede children, remain within the same Session, and Sessions cannot resume after closing.

## Tool-wait annotation

For non-root Continuations, the deterministic tool-wait decision may attach one duration from the explicit `tool_wait_seconds` set.

This models the structural pattern:

```text
Inference -> Tool wait -> Continuation
```

It does not modify the source arrival timestamp and does not claim the observed interarrival gap came from a real tool call.

## Fault-plan annotation

The deterministic fault decision may attach one configured C2 `FaultClass` to a source-linked annotation.

This is a policy-neutral synthetic fault plan only. C5.3 does not:

```text
mutate Continuity semantic state
mutate simulator resources
alter event delivery
change measured trace timing
execute recovery policy
```

Actual fault execution remains in the simulator/experiment layers.

## Integrity and canonical replay

`ContinuityAugmentationDataset` enforces:

- lowercase SHA-256 source fingerprint syntax;
- `SYNTHETIC` provenance only;
- exact schema/version;
- nonempty tuple of typed annotations;
- unique source `record_id` linkage inside the artifact;
- unique Continuation IDs;
- contiguous Session groups;
- root/non-root parent rules;
- parents precede children and remain same-Session;
- branch-group presence matches linear vs non-linear parenting;
- tool waits belong to configured duration choices;
- faults belong to configured `FaultClass` choices.

`assert_compatible_source()` then verifies exact source fingerprint plus one-to-one source-order record linkage.

`assert_reproducible()` regenerates the complete artifact from source/config/seed and requires byte-identical canonical JSON.

JSON parsing rejects duplicate members, non-finite constants, unknown/missing schema members, invalid enum values, malformed parent structure, and non-SYNTHETIC provenance.

Canonical JSON uses sorted keys, compact separators, explicit nulls, and `allow_nan=False`. The augmentation fingerprint is SHA-256 over those canonical UTF-8 bytes.

## Deterministic test coverage

C5.3 tests cover:

```text
source immutability and layer separation
explicit SYNTHETIC provenance
source fingerprint binding and record linkage
same source/config/seed => byte-identical artifact
changed seed/config => changed fingerprint
configuration dictionary-order independence
frozen deterministic replay vector
session boundaries and root rules
linear parent links with branching disabled
same-session configured-lookback branches
tool waits excluded from roots and selected only from explicit choices
faults selected only from configured C2 classes
zero-probability control
probability/type/range validation
unconfigured serialized tool-wait/fault rejection
canonical round trip
semantic tamper detection through reproduction
malformed parent/session-resumption rejection
unknown/missing/duplicate/non-finite JSON rejection
invalid provenance rejection
```

These fixtures prove deterministic mechanics only. They are not empirical evidence that the synthetic structures occur with the configured frequencies in Mooncake or another workload.

## Claim boundary

C5.3 supports:

```text
reproducible synthetic Continuity augmentation
explicit separation from source-derived workload facts
stable source/config/seed replay
policy-neutral synthetic fault planning
```

C5.3 does not support:

```text
real prevalence of Sessions, branches, tool waits, or failures
GPU timing or KV-transfer cost
cache-retention probability
policy efficiency superiority
H4/H5/H7 adjudication
```

## Exit

C5.3 closes after:

1. exact-head Python 3.11/3.12/3.13 deterministic CI is green;
2. bounded exact-head technical/scientific review finds no provenance, determinism, or source-separation blocker;
3. the reviewed exact head is SHA-fenced and squash-merged;
4. issue #96 and C5 umbrella #90 record the merge/review/CI provenance.

Then C5.4 integrates explicit workload modes: source-derived, trace-augmented, and fully synthetic.
