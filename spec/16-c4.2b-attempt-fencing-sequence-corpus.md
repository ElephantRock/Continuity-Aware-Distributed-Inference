## 1. Purpose

C4.2b extends the closed C4.2a deterministic S1 harness from the three mandatory traces into a bounded adversarial sequence corpus. It does not change C1, C2, C3, baseline information privileges, or the C4.1 correctness contract.

The slice evaluates whether timing, duplication, reordering, and repeated supersession can produce stale authoritative acceptance or duplicate semantic finalization that is not exposed by FTR1/FTR2/FTR3.

This is EV0 deterministic semantic evidence with `SYNTHETICALLY_GENERATED` provenance. It is not performance calibration.

## 2. Fixed measurement boundary

The C4.2a boundary remains authoritative:

```text
physical execution != placement admission != authoritative result acceptance
```

A physical stale Attempt completion is not a SAAR denominator event.

A SAAR opportunity is an exogenous stale terminal authority presentation that:

1. is declared in the case manifest before any policy executes;
2. targets an Attempt that the independent manifest oracle has already made stale through supersession;
3. has delivered physical `SUCCEEDED` execution before the authority presentation;
4. reaches `ContinuityAdapter`'s `finalize_request` path;
5. is classified after finalization so `SUPERSEDED -> COMMITTED` can be counted as a real violation rather than crashing the harness.

Normally the stale Attempt is `SUPERSEDED` immediately before finalization. For repeated presentations, if an earlier stale presentation has already been incorrectly accepted, the later presentation remains an oracle-stale SAAR opportunity even though the defective semantic state now exposes that Attempt as `COMMITTED`. The harness must continue classification rather than suppressing the later event with a precondition crash.

DFR remains policy-derived:

```text
numerator   = completed LogicalRequests semantically finalized more than once
denominator = completed LogicalRequests
```

O1/O2/O3/O4 and SSER remain operation-level under `cadi.correctness-evaluation.v1`.

## 3. Corpus manifest schema

Corpus schema:

`cadi.s1-attempt-fencing-sequence-corpus.v1`

Each `AttemptFencingSequenceManifest` contains:

```text
case_id
seed
pressure_labels
ordered actions
stale_presentation_event_ids
expected_committed_attempt_id
schema
```

Each action contains:

```text
kind
logical delivery time
event_id
string payload
```

Supported action kinds are:

```text
REQUEST
ATTEMPT_START
TIMEOUT
RETRY_START
COMPLETE
LATE_COMPLETE
OBSERVE
OBSERVE_DUPLICATE
```

For `OBSERVE_DUPLICATE`, the delivery EventID and delivery time are distinct, while the duplicated observation retains the original request/Attempt/Evidence/Output identity and original semantic observation timestamp. If the original `OBSERVE` explicitly supplies `observed_at`, that explicit timestamp is authoritative for duplicate identity even when it differs from the original delivery time. This models repeated delivery of the same observation rather than constructing a second observation with different semantic identity.

The ordered action list is itself part of the manifest fingerprint because same-time delivery order is semantically relevant in the deterministic event kernel.

The manifest fingerprint is SHA-256 over canonical JSON with sorted mapping keys and compact separators.

## 4. Independent oracle and public-input normalization discipline

The manifest is created before policy execution and fixes:

- request/Attempt generation structure;
- exact delivery ordering;
- exact stale authority-presentation EventIDs;
- expected authoritative Attempt;
- pressure/fault labels.

Runtime observation may validate those conditions, but it cannot decide retrospectively which events enter the denominator.

All public manifest inputs are normalized before replay and before ground-truth serialization. This applies both to direct `run_s1_sequence_trial(...)` calls and to caller-supplied `run_s1_sequence_paired(manifests=...)` inputs. Normalization is policy-independent and performs only representation repair required by the declared manifest semantics:

- true duplicate observations inherit the original semantic observation timestamp;
- an explicit original `observed_at` is preserved rather than replaced with delivery time;
- stale denominator EventIDs are canonicalized into deterministic delivery order;
- request/Attempt/Evidence/Output identity remains unchanged for true duplicates.

The normalized manifest—not the raw caller representation—is the manifest replayed, returned in trial/evaluation artifacts, fingerprinted for ground truth, and compared across B0–B4.

For every stale presentation the harness captures:

```text
before finalization:
  Attempt authority
  Attempt execution
  request current Attempt
  request committed Attempt
  whether a prior stale presentation has already been accepted

after finalization:
  Attempt authority
  Attempt execution
  request current Attempt
  request committed Attempt
  accepted_authoritatively
```

For the ordinary path, a manifest-labeled stale presentation must be `SUPERSEDED/SUCCEEDED`. If a previous stale presentation has already caused the same stale Attempt to become authoritative, a subsequent manifest-declared repeated presentation remains measurable as a stale input rather than being discarded or causing the trial to abort.

## 5. Bounded default corpus

The default corpus contains 17 explicit cases and 22 stale authority-presentation events.

### A. Timeout timing

```text
A-timeout-before-a1-success
A-timeout-after-a1-success
A-simultaneous-complete-then-timeout
A-simultaneous-timeout-then-complete
```

These cover timeout before physical success, timeout after success but before terminal observation, and both deterministic same-time delivery orders.

### B. Retry duplication / reorder

```text
B-duplicate-timeout
B-duplicate-retry-start
B-stale-retry-after-commit
B-delayed-retry-start
```

These cover repeated timeout delivery, repeated retry-start delivery, a stale retry-start after authoritative completion, and a delayed explicit retry-start.

### C. Late completion

```text
C-late-before-a2-complete
C-late-after-a2-complete
C-late-after-a2-commit
C-duplicate-late-success
```

These cover late A1 success before A2 completion, after A2 completion but before observation, after A2 authoritative commit, and duplicate late physical success delivery.

### D. Stale authority presentation

```text
D-stale-immediate-after-supersession
D-duplicate-stale-presentation
D-fresh-before-stale
```

These cover stale presentation immediately after supersession, true duplicate stale-presentation delivery with preserved observation identity, and fresh-before-stale terminal observation order.

### E. Repeated supersession

```text
E-three-generations-stale-before-commit
E-three-generations-stale-after-commit-duplicates
```

These create A1 -> A2 -> A3 using the closed timeout/retry APIs. Both A1 and A2 become stale authority-presentation candidates after A3 becomes current. One case presents both stale results before A3 commit; the other commits A3 first and then delivers repeated stale presentations for both prior generations.

## 6. Baseline fairness

Every normalized manifest is replayed independently against B0, B1, B2, B3, and B4.

All policies share the same C1 semantic authority and retain all ordinary correctness mechanisms already available under their closed C3 abstraction.

The experiment does not disable independent fencing in B0–B3 to create a B4 advantage.

B4 may still reject a stale physical-work admission probe with `ATTEMPT_FENCED`. That decision remains in `policy_decision` diagnostics and is not a SAAR opportunity or violation.

## 7. Metric construction

For each case/policy operation:

- every normalized-manifest stale-presentation EventID contributes one SAAR opportunity with scope `EXOGENOUS_PAIRED`;
- an EventID contributes a SAAR violation only if post-finalization authority commits that stale Attempt;
- repeated presentation EventIDs preserve event cardinality even when they carry the same duplicated observation identity;
- a completed request contributes one DFR opportunity with scope `POLICY_DERIVED`;
- DFR violates only when more than one `finalize_request` action is semantically `APPLIED`;
- semantic correctness compares the committed Attempt with the manifest's expected Attempt;
- all cases include retry recovery, so a correct completed operation is O2;
- an uncommitted terminal case is represented as explicit non-success rather than silently dropped.

Duplicate delivery and idempotent adapter processing do not by themselves constitute DFR violations.

## 8. Reproducibility obligations

The regression suite requires:

- 17 unique case IDs;
- 17 unique manifest fingerprints;
- pressure-family coverage A–E;
- canonical case-then-B0–B4 trial order;
- identical ground truth per case across policies;
- identical exogenous SAAR EventIDs per case across policies;
- every SAAR opportunity reaches `finalize_request`;
- every stale presentation has both pre- and post-finalization measurement;
- duplicate observation deliveries retain the original semantic identity and original observation timestamp;
- an original explicit `observed_at` is preserved through duplicate normalization;
- raw/generated-style caller manifests normalize identically through both public entry points before replay and ground truth;
- repeated stale acceptance remains classifiable after a prior bad stale commit rather than crashing the trial;
- duplicate delivery cases retain one semantic applied finalization under the correct C1 implementation;
- repeated-supersession cases end with A3 authoritative when the closed C1 semantics are correct;
- deterministic replay produces stable evaluation fingerprints.

## 9. Measurement-integrity repairs

Six construction/measurement findings were repaired before final review.

1. **Duplicate observed-at conflict.** The initial generated duplicate reused the same Evidence/Output identity but assigned the later delivery time as its observation time. `ContinuityAdapter` correctly rejected that conflicting Evidence identity before `finalize_request`, so the declared SAAR event was not actually exercised.
2. **Stale EventID ordering.** The four stale presentations in the three-generation duplicate case were initially declared in generation-grouped order rather than deterministic delivery order.
3. **Incorrect workaround weakened duplicate semantics.** An intermediate repair avoided the timestamp conflict by assigning a new Evidence/Output identity to repeated stale deliveries. That made the suite green, but it no longer represented a true duplicate observation. The final repair preserves the original Evidence/Output identity and original observation timestamp while retaining a distinct delivery EventID.
4. **Repeated-presentation false-zero path.** The replay originally required every manifest-labeled stale presentation to observe `SUPERSEDED` immediately before finalization. If the first stale presentation were incorrectly accepted, a later repeated presentation would see the stale Attempt as `COMMITTED` and crash before classification. The final classifier allows this state only when it is causally attributable to a prior stale authoritative acceptance and continues counting subsequent stale presentations.
5. **Caller-supplied normalization bypass.** The validated default corpus was normalized, but a raw/generated-style manifest passed directly to `run_s1_sequence_trial` or through `run_s1_sequence_paired(manifests=...)` could bypass normalization, reintroducing duplicate timestamp conflicts or stale-EventID ordering failures. Both public entry points now normalize before replay, ground truth, and returned artifacts; regression coverage exercises the raw generated-style public path.
6. **Explicit original observation time lost during normalization.** The normalizer initially recorded `action.at` for an original `OBSERVE` even when its payload supplied an earlier explicit `observed_at`. A later duplicate could therefore inherit the wrong timestamp and conflict under the same Evidence identity. The normalizer now derives the original semantic time from `payload.get("observed_at", action.at)`, and a regression verifies explicit-time preservation plus successful finalization of every declared SAAR presentation.

All repairs occur in the C4.2b experiment layer before or around replay. C1, C2, C3, policy semantics, and baseline privileges remain unchanged. Manifest normalization remains policy-independent and occurs before B0–B4 execution.

## 10. Expected interpretation

C4.2b does not assume a B4 semantic advantage.

If competent B0–B3 and B4 all remain at zero SAAR, zero DFR, and zero SSER across the full bounded corpus, that is a legitimate semantic null comparator result. The novelty claim for H1 must then remain narrowed unless C4.2c or later evidence demonstrates a real correctness distinction or shows that a weaker abstraction must reproduce equivalent Continuity authority to remain correct.
