
```text

S2B-COMMITTED-PRODUCER-CONTROL
```

The adversarial case creates State from A1 while A1 is CURRENT, then advances through A2 to committed A3. The physical A1 State remains VALID while its producing Attempt becomes SUPERSEDED.


These cases pressure the Paper-1 same-Attempt Phase ordering rule:

```text

```

The later-Phase control is valid under exact C1 `ExecutionContext` semantics.

The same-Phase, earlier-Phase, and no-consumer-Phase cases are incompatible.

## D — Derived-State dependency

The top-level candidate remains physically plausible and may remain logically `VALID`, while recursive dependency semantics determine compatibility.

## E — State validity

```text

S2E-VALID-CONTROL
```

The adversarial case retains a physically `VALID` replica of a logically `INVALID` State. The control preserves ordinary valid ancestor reuse.

# 3. Independent exact-context oracle

C4.3b does not call either:

```text
ContinuityCore.is_ancestor(...)
ContinuityCore.state_compatible(...)
```

inside its independent compatibility oracle.

The oracle independently evaluates:

```text
Program/Session/Continuation/Request/Attempt linkage
CURRENT consumer Attempt authority
consumer Phase linkage/status when present
Continuation ancestry
StateValidity
producer Attempt authority
committed producer Request identity
same-Attempt producer/consumer Phase ordering
recursive derived_from dependency compatibility
```

The result is then compared with direct C1:

```text
core.state_compatible(candidate, exact_execution_context)
```

Any disagreement aborts the trial rather than becoming policy-visible evidence.

The validated corpus regression requires oracle/C1 agreement for every policy/case pair.

# 6. Metric causality

## WBRR

Exogenous paired WBRR opportunities exist only for:

```text

S2A-DEEP-ABANDONED
```

A violation requires an actual incompatible `StateConsumptionEvent`.

## WSCR

WSCR remains policy-derived. A denominator exists only when an actual State-consumption event occurs during a faulted operation.

## SSER

Application effects remain independent of compatibility and Gate metrics.

The ten faulted incompatible cases intentionally use:

```text

DETECT_AND_RECOMPUTE   3 cases
CORRECT_RESULT         3 cases
```

Therefore incompatible consumption can produce O4, O2, or O1.
