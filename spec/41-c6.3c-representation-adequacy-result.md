## Multi-token decode composition

C6.3a explicitly warned that validating the single-token family does not establish correctness of C6.1 multi-token decode composition.

For the FIT-derived single-token affine primitive:

```text
step(context) = fixed + slope * context
```

repeated composition over `m` output tokens from input context `n` is:

```text
source_primitive_sequence =
    m * fixed
    + slope * (m*n + m*(m-1)/2)
```

Frozen C6.1 mechanics instead apply the fixed term once:

```text
c6_1_sequence =
    fixed
    + slope * (m*n + m*(m-1)/2)
```

Therefore:

```text
source_primitive_sequence - c6_1_sequence
= (m - 1) * fixed
```

The C6.3c issue froze the analytic grid before evaluation:

```text
input_context_tokens = [32, 256, 1024, 2048, 4032]
output_tokens        = [2, 4, 8, 16, 32]
max_model_len        = 4096
```

All 25 pairs satisfy the declared length bound.

This check is explicitly `ANALYTICALLY_DERIVED`. It is a mechanics-composition test using the FIT-derived single-token affine primitive; it is not an additional physical A100/H100 measurement.
