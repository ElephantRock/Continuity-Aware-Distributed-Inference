# 1. Research boundary

C4.4a begins S3 Binding Safety without changing C1, C2, C3, the baseline information contracts, or the C4.1 correctness schema.

The canonical Binding safety rule is:

```text
ownership-sensitive commit(y, e) => e == CurrentEpoch(y)
```

Safe migration additionally requires one authoritative semantic transition of:

```text
(CurrentEpoch, ActiveBinding)
```

only after sufficient evidence.

The primary invariant families are:

```text
D1  Single Current Binding Epoch
D2  Binding Epoch Monotonicity
D3  Stale Binding Fencing
D4  Migration Has One Commit Point
D5  Migration Evidence Sufficiency
F3  Reordered Observation Safety
Composite Safe Migration
```

# 2. Measurement boundary

C4.4a preserves five distinct stages:

```text
physical transfer/materialization observation
!= policy migration admission
!= authoritative C1 migration commit
!= later stale/conflicting Binding presentation
!= operation-level semantic result
```

A physical destination appearing, a B4 `ALLOW_COMMIT` decision, or a stale source message is not itself a Binding-authority change.

Authoritative Binding state is defined only by the C1 state:

```text
current_binding_by_subject
current_epoch_by_subject
Binding.status
```

SBDR is classified after the binding-sensitive presentation has executed against the real C1 commit path.

# 3. Baseline fairness

The frozen C3 information contracts remain unchanged:

```text
B0  request/load only
B1  candidate-key cache locality
B2  session affinity + B1
B3  exact StateID + precise State location, Binding-blind
B4  complete Continuity information including BindingID, Binding epoch, and reconciliation
```

Only B4 has the frozen `decide_migration(...)` policy surface.

All competent B0–B4 baselines remain subject to the same authoritative C1 `commit_migration(...)` semantics. C4.4a does not bypass the common C1 base-epoch/evidence guard for B0–B3 merely to manufacture an H6 comparator distinction.

Therefore a B4 `WAIT` or `ALLOW_COMMIT` decision is recorded as policy evidence, but only the C1 authoritative outcome determines SBDR and semantic correctness.

# 4. Deterministic corpus

The C4.4a corpus contains five scenarios:

```text
S3-PARTIAL-MIGRATION
S3-STALE-EPOCH-CANDIDATE
FTR8-LATE-OLD-OWNER
S3-CONCURRENT-MIGRATION
S3-SUCCESS-CONTROL
```

Four are faulted and carry one fixed exogenous SBDR presentation EventID each. The success control is non-faulted and carries no Gate denominator event.

## 4.1 S3-PARTIAL-MIGRATION

Initial authority:

```text
b1 / W1 / epoch 1 / ACTIVE
```

Candidate:

```text
b2 / W2 / epoch 2 / MIGRATING
```

A physical partial-materialization observation exists, but no migration-commit Evidence exists.

Observed deterministic behavior:

```text
B4 migration admission = WAIT
C1 commit attempt       = rejected for insufficient Evidence
final authority         = b1 / epoch 1
```

Transfer start or destination presence therefore does not create ownership authority.

## 4.2 S3-STALE-EPOCH-CANDIDATE

Two candidates are created while epoch 1 is current:

```text
b2 / epoch 2 / base 1
b3 / epoch 3 / base 1
```

`b2` commits first. The delayed `b3` presentation then arrives with otherwise valid commit Evidence.

Observed deterministic behavior:

```text
CurrentEpoch = 2
b2 = ACTIVE
b3 commit rejected because base_epoch 1 is stale
```

The frozen B4 admission surface reports `ALLOW_COMMIT` for the reconciled stale candidate, but C1 rejects its stale base epoch. This is intentional evidence that semantic stale-epoch fencing resides in the common C1 authority and is not relabeled policy behavior.

## 4.3 FTR8-LATE-OLD-OWNER

After migration commits:

```text
b2 / W2 / epoch 2 / ACTIVE
b1 / W1 / epoch 1 / SUPERSEDED
```

a delayed old-owner Binding presentation for `b1 / epoch 1` arrives.

Observed deterministic behavior:

```text
late epoch-1 presentation rejected
b2 / epoch 2 remains authoritative
```

The closed C1 prototype exposes Binding-authority mutation through `commit_migration(...)`; this EV0 trace therefore represents the late old-owner operation as a stale Binding commit presentation rather than inventing a new ownership-sensitive core API for the experiment.

## 4.4 S3-CONCURRENT-MIGRATION

Two candidates exist concurrently:

```text
b2 / W2 / epoch 2 / base 1
b3 / W3 / epoch 3 / base 1
```

Both may be B4-admitted before either commits. `b2` wins the semantic commit. The later `b3` commit presentation fails because its base epoch is no longer current.

Observed deterministic behavior:

```text
one authoritative winner only
CurrentEpoch remains 2
b2 ACTIVE
b3 non-authoritative
```

## 4.5 S3-SUCCESS-CONTROL

A reconciled next-epoch candidate with sufficient `EXACT_OBSERVATION` Evidence commits normally:

```text
b1 / epoch 1 -> SUPERSEDED
b2 / epoch 2 -> ACTIVE
CurrentEpoch = 2
```

This proves Binding safety is not obtained by globally disabling migration.

# 5. Oracle and classification boundary

The deterministic corpus declares the expected authoritative Binding/epoch sequence independently of policy output. The evaluation does not ask a policy whether a Binding is current.

The executable regressions additionally pin the canonical expected final epochs (`1` or `2`, by scenario) rather than accepting arbitrary generated epoch values as evidence of correctness.

For every SBDR presentation, the classifier compares post-presentation C1 authoritative state against the expected pair:

```text
(expected BindingID, expected epoch)
```

A violation exists only when the stale/conflicting presentation leaves or moves authoritative state under wrong Binding authority. Rejected, WAITed, or failed stale operations are not SBDR violations.

# 6. Metric contract

## SBDR

Every faulted scenario declares exactly one exogenous paired EventID before policy execution:

```text
S3-PARTIAL-MIGRATION
S3-STALE-EPOCH-CANDIDATE
FTR8-LATE-OLD-OWNER
S3-CONCURRENT-MIGRATION
```

EventID cardinality and identity are identical across B0–B4.

Validated deterministic denominator:

```text
4 SBDR opportunities per policy
```

A violation requires actual authoritative divergence after the corresponding presentation.

## SSER

The four faulted operations form the SSER denominator. Partial migration is explicit non-success (`WAIT`); stale/concurrent/late-event cases preserve correct authority transparently. The success control is not faulted.

# 7. Anti-false-zero regression

The harness includes a private execution-plane corruption hook used only by regression tests. The hook runs after the real C1 commit path and forcibly installs the presented stale/conflicting Binding as current authority.

The classifier then records:

```text
SBDR violation = yes
O4              = yes
```

This demonstrates that C1 rejection or invariant checks do not make a true Binding divergence unmeasurable. The corruption hook is not part of the public paired experiment API and is not evidence about normal C1 behavior.
