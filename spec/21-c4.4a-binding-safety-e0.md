# 1. Research boundary

C4.4a begins S3 Binding Safety without changing C1, C2, C3, the baseline information contracts, or the C4.1 correctness schema.

The canonical Binding safety rule is:

```text
ownership-sensitive commit(y, e) => e == CurrentEpoch(y)
```

Safe migration additionally requires one authoritative semantic transition of:

```text
(CurrentEpoch, ActiveBinding)
```

only after sufficient evidence.

The primary invariant families are:

```text
D1  Single Current Binding Epoch
D2  Binding Epoch Monotonicity
D3  Stale Binding Fencing
D4  Migration Has One Commit Point
D5  Migration Evidence Sufficiency
F3  Reordered Observation Safety
Composite Safe Migration
```

# 2. Measurement boundary

C4.4a preserves five distinct stages:

```text
physical transfer/materialization observation
!= policy migration admission
!= authoritative C1 migration commit
!= later stale/conflicting Binding presentation
!= operation-level semantic result
```

A physical destination appearing, a B4 `ALLOW_COMMIT` decision, or a stale source message is not itself a Binding-authority change.

Authoritative Binding state is defined only by the C1 state:

```text
current_binding_by_subject
current_epoch_by_subject
Binding.status
```

SBDR is classified after the binding-sensitive presentation has executed against the real C1 commit path.

# 3. Baseline fairness

The frozen C3 information contracts remain unchanged:

```text
B0  request/load only
B1  candidate-key cache locality
B2  session affinity + B1
B3  exact StateID + precise State location, Binding-blind
B4  complete Continuity information including BindingID, Binding epoch, and reconciliation
```

Only B4 has the frozen `decide_migration(...)` policy surface.

However, all competent B0–B4 baselines remain subject to the same C1 authoritative `commit_migration(...)` semantics.

C4.4a must not bypass the common C1 base-epoch/evidence guard for B0–B3 merely to manufacture an H6 comparator distinction.

Therefore a B4 `WAIT` or `ALLOW_COMMIT` decision is recorded as policy evidence, but only the C1 authoritative outcome determines SBDR and semantic correctness.

# 4. Deterministic corpus

The C4.4a corpus contains five scenarios.

```text
S3-PARTIAL-MIGRATION
S3-STALE-EPOCH-CANDIDATE
FTR8-LATE-OLD-OWNER
S3-CONCURRENT-MIGRATION
S3-SUCCESS-CONTROL
```

Four are faulted and carry one fixed exogenous SBDR presentation EventID each.

The success control is non-faulted and carries no Gate denominator event.

## 4.1 S3-PARTIAL-MIGRATION

Initial authority:

```text
b1 / W1 / epoch 1 / ACTIVE
```

Candidate:

```text
b2 / W2 / epoch 2 / MIGRATING
```

A physical partial-materialization observation exists, but no migration-commit Evidence exists.

Expected:

```text
B4 migration admission = WAIT
C1 commit attempt       = rejected for insufficient Evidence
final authority         = b1 / epoch 1
```

This is the deterministic form of the partial-migration safety requirement: transfer start or destination presence does not create ownership authority.

## 4.2 S3-STALE-EPOCH-CANDIDATE

Two candidates are created while epoch 1 is current:

```text
b2 / epoch 2 / base 1
b3 / epoch 3 / base 1
```

`b2` commits first.

The delayed `b3` commit presentation then arrives with otherwise valid commit Evidence.

Expected:

```text
CurrentEpoch = 2
b2 = ACTIVE
b3 commit rejected because base_epoch 1 is stale
```

The B4 admission layer may still report `ALLOW_COMMIT` because its frozen policy surface records Binding ID/epoch/reconciliation but does not itself mutate or replace C1 epoch authority.

This intentionally verifies that the semantic stale-epoch fence is the common C1 authority rather than a relabeled policy decision.

## 4.3 FTR8-LATE-OLD-OWNER

After migration commits:

```text
b2 / W2 / epoch 2 / ACTIVE
b1 / W1 / epoch 1 / SUPERSEDED
```

a delayed old-owner presentation for `b1 / epoch 1` arrives.

Expected:

```text
late epoch-1 presentation rejected
b2 / epoch 2 remains authoritative
```

## 4.4 S3-CONCURRENT-MIGRATION

Two physical migration candidates exist concurrently:

```text
b2 / W2 / epoch 2 / base 1
b3 / W3 / epoch 3 / base 1
```

Both may be policy-admitted before either commits.

`b2` wins the semantic commit.

The later `b3` commit presentation must fail because its base epoch is no longer current.

Expected:

```text
one authoritative winner only
CurrentEpoch remains 2
b2 ACTIVE
b3 non-authoritative
```

## 4.5 S3-SUCCESS-CONTROL

A reconciled next-epoch candidate with sufficient `EXACT_OBSERVATION` Evidence commits normally.

Expected:

```text
b1 / epoch 1 -> SUPERSEDED
b2 / epoch 2 -> ACTIVE
CurrentEpoch = 2
```

This proves Binding safety is not obtained by globally disabling migration.

# 5. Independent oracle

The deterministic oracle declares the expected final authoritative Binding and epoch from the scenario manifest and event order.

It does not ask the policy whether a Binding is current.

For every SBDR presentation, the classifier compares the post-presentation C1 authoritative state against the independent expected pair:

```text
(expected BindingID, expected epoch)
```

A violation exists only when the stale/conflicting presentation leaves or moves authoritative state under the wrong Binding authority.

Rejected, WAITed, or failed stale operations are not SBDR violations.

---

# 6. Metric contract

## SBDR

Every faulted scenario declares exactly one exogenous paired EventID before policy execution.

```text
S3-PARTIAL-MIGRATION
S3-STALE-EPOCH-CANDIDATE
FTR8-LATE-OLD-OWNER
S3-CONCURRENT-MIGRATION
```

The EventID cardinality and identity are identical across B0–B4.

Expected deterministic denominator:

```text
4 SBDR opportunities per policy
```

A violation requires actual authoritative divergence after the corresponding presentation.

## SSER

The four faulted operations form the SSER denominator.

The partial-migration case is expected to be explicit non-success (`WAIT`) rather than silent success.

The stale/concurrent/late-event cases are expected to preserve correct authority transparently.

The success control is not faulted.

---

# 7. Anti-false-zero requirement

The harness includes an internal execution-plane corruption hook used only by regression tests.

The hook runs **after** the real C1 commit path and forcibly installs the presented stale/conflicting Binding as current authority.

The classifier must then record:

```text
SBDR violation = yes
O4              = yes
```

This prevents a measurement path where C1 rejection or invariant assertions make it impossible to observe a true Binding divergence.

The corruption hook is not part of the public paired experiment API and is not evidence about normal C1 behavior.

C4.4a may merge only after:

```text
5-case deterministic corpus is reproducible
4 exogenous paired SBDR opportunities are identical across B0–B4
partial migration cannot commit without evidence
late old-owner epoch cannot regain authority
concurrent candidates produce one semantic winner
success control commits the next epoch normally
anti-false-zero corruption produces SBDR + O4
no C1/C2/C3 semantic or information-contract changes
Python 3.11 / 3.12 / 3.13 CI green on exact head
bounded exact-head review finds no substantive correctness/measurement issue
```

C4.4a alone does not close H6/S3. C4.4b adversarial EV0 and C4.4c distributed EV1 remain required.
