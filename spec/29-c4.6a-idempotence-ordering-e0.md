# C4.6a — Deterministic S5 Idempotence / Ordering EV0

Status: candidate implementation for issue #84 under C4.6/S5 #83.

Base milestone: `586107f20bc09c558bc28a7a6886947557682faf` (C4.5/S4 closure).

## Purpose

This slice evaluates the deterministic part of S5 without changing the closed C1/C2/C3 semantic contract. The target properties are semantic commit idempotence, duplicate-observation safety, monotonic authority under replay/reordering, and completed-request output immutability.

The primary Gate metric is Duplicate Finalization Rate (DFR). SSER plus independently recorded invariant/snapshot violations are secondary safety signals.

## DFR denominator semantics

DFR remains a `POLICY_DERIVED` metric:

```text
DFR = LogicalRequests finalized more than once semantically
      / completed LogicalRequests
```

A DFR opportunity is created only when the evaluated faulted operation actually reaches a completed LogicalRequest. The opportunity identity is derived from that concrete completion. Faulted non-request operations retain a null DFR denominator rather than being reported as numeric zero-rate evidence.

The nonfaulted positive-control finalization does not create a Gate opportunity because the correctness-evaluation contract does not attach Gate opportunities to nonfaulted operations.

## Independent finalization accounting

The experiment does not define duplicate finalization from `finalize_request`'s return value. For request cases it snapshots authoritative Request/Attempt state before and after every semantic application and records a finalization effect whenever the authoritative completed output changes from the prior snapshot.

Thus a second authoritative output transition is observable even if the runtime method under test would normally reject it. The private anti-false-zero path mutates the post-safe runtime state only after the real duplicate replay has completed, injects a second authoritative output transition, and must classify the result as DFR violation plus O4.

## Canonical deterministic corpus

The predeclared eight cases are:

```text
S5-D1-SAME-OUTPUT-FINALIZE-TWICE
  O1 finalizes successfully, then the same O1 finalization is replayed.
  Expected: one authoritative finalization effect; replay is idempotent.
  DFR opportunity: yes.

S5-D2-CONFLICTING-OUTPUT-AFTER-COMPLETION
  O1 finalizes, then terminal O2 is presented for the already-completed request.
  Expected: O2 rejected and O1 remains immutable.
  DFR opportunity: yes.

S5-D3-DUPLICATE-SEMANTIC-EVENT-ID
  One SemanticEvent is recorded twice with identical identity and payload.
  Expected: one stored event and one event-order entry.
  DFR opportunity: no.

S5-D4-CONFLICTING-DUPLICATE-EVENT-ID
  The same EventID is replayed with a different semantic payload.
  Expected: conflicting replay rejected; original event retained exactly.
  DFR opportunity: no.

S5-D5-DUPLICATE-MIGRATION-COMMIT
  A migration commits from b1 to b2, then the same candidate commit is replayed.
  Expected: replay cannot advance Binding authority or epoch a second time.
  DFR opportunity: no.

S5-D6-TERMINAL-CONTINUATION-REPLAY
  TERMINAL lifecycle is replayed, then an ACTIVE resurrection is attempted.
  Expected: terminal replay is idempotent; resurrection rejected.
  DFR opportunity: no.

S5-D7-INVALID-STATE-REPLAY
  INVALID State validity is replayed, then VALID resurrection is attempted.
  Expected: invalidation replay is idempotent; resurrection rejected.
  DFR opportunity: no.

S5-D8-FIRST-VALID-FINALIZATION-CONTROL
  First valid terminal output finalizes normally.
  Expected: request COMPLETED, attempt COMMITTED, authoritative output O1.
  DFR opportunity: no (nonfaulted control).
```

D1-D7 are faulted operations; D8 is the positive control.

## Baseline fairness

All B0-B4 execute the same deterministic semantic cases through the common closed C1 machinery. No request immutability, EventID deduplication, Binding epoch fence, lifecycle monotonicity rule, or other common correctness guard is disabled for B0-B3. No policy-specific S5 information is consumed by this deterministic slice.

A semantic null comparator across B0-B4 is therefore an acceptable and expected result if the shared mechanism is sufficient.
