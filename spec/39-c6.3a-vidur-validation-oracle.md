# C6.3a — Vidur reference-composition and validation oracle

Status: candidate under issue #108 / parent #107 / C6 umbrella #102.

Base: exact C6.2 closure main `ebd4a81be6d168b82a29fdd4401c4623b9a85346`.

## Purpose

C6.3a freezes the semantics used to derive and judge source-backed reference points before C6.3b fits any CADI inference-cost coefficient. The intended failure mode is explicit: if the C6.1 representation cannot reproduce the declared source domain within the predeclared error budget, C6.3c reports `INADEQUATE_REVISE_REPRESENTATION` rather than hiding residuals or narrowing the domain after seeing results.

This slice does **not** fit a cost profile and does not claim CADI executed on A100 or H100 hardware.

The pinned predictor filters compute rows to the selected model architecture and tensor-parallel degree. It models component compute times against token count, models prefill attention using KV-cache size plus squared prefill-chunk size, and models decode attention using batch size plus KV-cache size. The linear-regression predictor is polynomial-feature regression, not an assumption that every source component is first-order linear. When `time_stats.attn_kv_cache_save.median` is absent from an attention profile, the pinned predictor explicitly fills that component with zero; C6.3 reference derivation must preserve that source behavior rather than invent a nonzero value.

Vidur's `ExecutionTime.model_time` forms a per-layer attention-plus-MLP block time, multiplies it by the number of layers in the pipeline stage, adds pipeline communication, and converts milliseconds to seconds. CPU overhead is part of `total_time`, not `model_time`.

## Declared first reference domain

C6.3b/c must use the following first profile domain unless a later reviewed slice explicitly revises it:

```text
model                 meta-llama/Llama-2-7b-hf
hardware              a100-80gb | h100-80gb
layers                 32
pipeline stages        1
tensor parallel        1
attention block size   16
attention backend      FLASH_ATTENTION
max model length       4096
compute modes          cold prefill; single-token decode
network mode           point-to-point send/recv vs byte size
```

The narrow TP1/PP1 domain is intentional. It prevents tensor-parallel all-reduce or pipeline-parallel send/recv costs from being silently absorbed into the first compute coefficients. Point-to-point network transfer is fitted and validated as its own family.

## Compute reference composition

A source-backed compute point reproduces the TP1/PP1 form of Vidur `ExecutionTime.model_time`:

```text
per-layer-ms =
    attn_pre_proj
  + attn_post_proj
  + attn_rope
  + attn_kv_cache_save
  + attention_kernel
  + input_layernorm
  + post_attention_layernorm
  + mlp_up_proj
  + mlp_down_proj
  + mlp_act
  + add

model-seconds = per-layer-ms * 32 * 1e-3
```

`attention_kernel` is exactly one of:

```text
cold prefill        time_stats.attn_prefill.median
single-token decode time_stats.attn_decode.median
```

At TP1/PP1, tensor-parallel and pipeline-parallel communication contributions are zero by construction. CPU scheduling/runtime overhead, embedding, and final softmax are outside this first compute reference because they are not part of Vidur `model_time` and were not frozen as C6.2 physical calibration inputs.

Cold-prefill source rows must satisfy:

```text
batch_size = 1
kv_cache_size = 0
prefill_chunk_size > 0
is_prefill = True
num_tensor_parallel_workers = 1
block_size = 16
max_model_len = 4096
attention_backend = FLASH_ATTENTION
```

Single-token-decode source rows must satisfy:

```text
batch_size = 1
prefill_chunk_size = 0
kv_cache_size > 0
is_prefill = False
num_tensor_parallel_workers = 1
block_size = 16
max_model_len = 4096
attention_backend = FLASH_ATTENTION
```

The independent axis is input tokens for cold prefill and context tokens for single-token decode. For one output token, C6.1 `decode_context_token_steps` equals that context-token count, so this source domain maps directly onto the C6.1 decode independent variable.

## Source-reference identity

Every derived `CalibrationReferencePoint` records:

```text
point ID
hardware ID
reference kind
independent-axis value and unit
observed seconds
derivation ID
pinned Vidur commit
exact source path + Git blob SHA references
```

The oracle does not accept arbitrary provenance strings. It resolves the selected hardware against the frozen C6.2 manifests and requires the source-artifact set to match exactly:

```text
cold prefill / single-token decode:
  MODEL_CONFIG + COMPUTE_ATTENTION + COMPUTE_MLP

point-to-point transfer:
  NETWORK_SEND_RECV
```

This binds the 32-layer model identity and every physical timing input used by the first reference derivation to the exact C6.2 source family. Reference source-artifact order is nonsemantic and canonicalized for serialization. Missing roles, wrong-hardware blobs, extra artifacts, or another upstream commit fail closed.

## Deterministic fit / validation split

Within one `(hardware_id, reference_kind)` family:

1. Require unique point IDs and unique independent-axis values.
2. Sort by `(axis_value, point_id)`.
3. Assign zero-based even ordinals to `FIT`.
4. Assign zero-based odd ordinals to `VALIDATION`.
5. Require at least two FIT and two VALIDATION points.

The split is intentionally fixed before coefficient fitting. `ReferencePartition` independently revalidates the canonical parity assignment, so constructing a partition directly cannot move a difficult point from validation into fit.

## Error oracle

For each validation point:

```text
signed error = predicted_seconds - observed_seconds
absolute error = abs(signed error)
APE = absolute error / observed_seconds, only when observed_seconds > 0
```

If `observed_seconds == 0`, APE is `null`; the point remains in MAE and in an explicit `zero_reference_count`. A zero-reference point passes only if absolute error is exactly zero.

Aggregate validation report:

```text
MAE      mean absolute error over all validation points
MAPE     mean APE over nonzero validation references only
max APE  maximum APE over nonzero validation references
zero-reference count
```

If a family has no nonzero validation reference, MAPE/max-APE are null and the family is inadequate because the percentage-error gate cannot be evaluated.

Prediction keys must match the held-out point IDs exactly. Missing or extra predictions fail closed rather than being ignored.

## Predeclared adequacy gate

A family receives `ADEQUATE_WITHIN_DECLARED_DOMAIN` only when all are true:

```text
MAPE <= 0.05
max APE <= 0.10
every zero-reference point has exactly zero absolute error
```

Otherwise the family receives `INADEQUATE_REVISE_REPRESENTATION`.

Because APE/MAPE require subtraction and division, an exact mathematical boundary can land a few binary floating-point ULPs above the declared decimal threshold. The implementation therefore admits a fixed boundary budget of at most **8 ULPs of the threshold value**. That budget is serialized in the validation report and is not a material percentage tolerance band; errors outside the fixed 8-ULP boundary fail the gate.

The 5% aggregate budget is predeclared before CADI fitting and is deliberately aligned with the published MLSys 2024 Vidur fidelity claim that the validated simulator estimates latency/throughput with less than 5% error in the reported evaluation regime. This does not mean CADI inherits Vidur's physical-validation error; it sets a conservative approximation budget for projecting Vidur's source model into the simpler C6.1 representation.

## Scientific boundary

C6.3a establishes the oracle only. It does not:

- freeze a derived timing-point corpus;
- fit A100 or H100 CADI coefficients;
- create a calibrated `InferenceCostProfile`;
- adjudicate H4, H5, or H7;
- claim GPU execution by CADI;
- permit a failed representation to be rescued by post-hoc threshold/domain changes.

The single-token decode family is a calibration/reference primitive, not by itself a proof that C6.1 correctly composes **multi-token** decode sequences. C6.1 currently applies its decode fixed term once to the whole output sequence while source execution has a per-step structure. Parent C6.3 therefore remains obligated to validate multi-token sequence composition before it can close; a failure there is a representation failure even if the single-token family passes.

C6.3b next derives the exact A100/H100 reference corpus and fits coefficients using only FIT points. C6.3c evaluates held-out points with this frozen oracle and records the representation-adequacy decision.
