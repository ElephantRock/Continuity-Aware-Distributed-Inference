# C6.4g — Dependency-Free Runtime Integration of Validated v4 Costs

Status: implementation gate for issue #130.

## 1. Purpose

C6.4f closed the representation-adequacy question for the finite pinned Vidur source-model
domain. It established exact source equivalence for representation v4 on every accepted
prefill and point-to-point transfer axis for both frozen hardware identities. C6.4g does
not perform another calibration, fit, timing probe, holdout evaluation, or representation
revision.

C6.4g is the deployment seam from that accepted scientific artifact into ordinary CADI
simulation. Its job is to make the accepted finite-domain values usable by the simulator
without requiring NumPy, scikit-learn, Vidur, or a pinned BLAS implementation at request
time.

The scientific evidence class remains:

`SIMULATED_SOURCE_MODEL_DERIVED_P_SRC2`

This is source-model evidence, not direct hardware measurement.

## 2. Frozen parent evidence

The runtime projection is accepted only from the exact C6.4f canonical artifact:

- artifact: `artifacts/c6.4f/exhaustive-source-equivalence.json`
- result schema: `cadi.c6.4f.exhaustive-source-equivalence-result.v1`
- result kind: `EXHAUSTIVE_FINITE_DECLARED_DOMAIN_SOURCE_EQUIVALENCE`
- representation:
  `cadi.c6.cost-representation.v4.source-ordered-polynomial+source-linear-algebra+decode-step-affine`
- decision: `ADEQUATE_WITHIN_DECLARED_DOMAIN`
- scientific fingerprint:
  `cc1b62c4e38a1612720f601375c425c0bd7d67b4eff11b101bfdf87b79a7a61a`
- artifact SHA-256:
  `93990386135ecbf6fc38e579841eace3431a068b10ee59209fe6ad7084bd8889`

The runtime loader hashes the artifact bytes before parsing them, then verifies the frozen
schema, representation, evidence class, decision, boundary accounting, post-hoc-repair
record, scientific fingerprint, and both hardware records. It also recomputes the
scientific fingerprint from the canonical JSON payload with the fingerprint field removed.

Any drift fails closed.

## 3. Runtime data projection

`simulator.inference_cost_runtime` extracts only already-adjudicated values from C6.4f:

- the 4,096 accepted v4 cold-prefill values for each hardware identity;
- the 4,096 accepted v4 send/receive values for each hardware identity;
- the carried C6.3 decode intercept and slope recorded by the passing C6.4f decode check;
- the passing state-size and memory-capacity scalars recorded by C6.4f.

No polynomial is evaluated. No source model is fit. No scientific runtime is imported.
No value is smoothed, rounded, clipped, extrapolated, or repaired.

The loader additionally requires every accepted prefill/transfer point to have zero ULP
distance, equal `source_seconds` and `v4_seconds`, and the exact frozen axis identity.

## 4. Request-time contract

The runtime public request shape remains `InferenceCostWorkload` so callers do not need a
second workload vocabulary. Legacy `simulator/inference_cost.py` remains unchanged and is
still the C6.1 affine contract; callers select validated v4 explicitly through
`simulator.inference_cost_runtime`.

For a workload with input length `n`, output count `m`, reusable prefix `r`, and state-token
count `s`:

### Prefill

- `n = 0` -> exactly `0.0` seconds.
- `1 <= n <= 4096` -> exact C6.4f table lookup.
- otherwise -> fail closed.

### Decode

The carried C6.3 primitive is composed as:

`steps = m*n + m*(m-1)/2`

`decode = m*fixed_per_output_token + slope_per_context_token_step*steps`

for `m > 0`, and exactly zero for `m = 0`.

The fixed term is therefore paid once per output token. The superseded C6.1 composition
that paid the fixed term once per sequence is not used by this runtime surface.

### Recompute

`recompute_tokens = n - r`

Recompute is the same accepted prefill lookup evaluated at `recompute_tokens`. Because
`InferenceCostWorkload` already enforces `0 <= r <= n`, this remains within the prefill
domain whenever `n` is accepted.

### State and memory

`state_bytes = state_fixed_bytes + state_bytes_per_token*s`

`memory_fraction = state_bytes / memory_capacity_bytes`

The state and capacity scalars are the unchanged values that C6.4f carried and checked.

### Transfer

- zero bytes -> exactly `0.0` seconds;
- positive bytes must be an exact multiple of 8,192 bytes;
- the resulting predictor-token key must be in `1..4096`;
- otherwise -> fail closed.

No request-time extrapolation is permitted.

## 5. Simulator integration

The generic `ResourceModel` remains provider-neutral. Its network links continue to use
their explicit latency/bandwidth mechanics; C6.4g does not overwrite `start_transfer()`.

`enqueue_validated_inference_task(...)` is an additive adapter:

1. evaluate the validated runtime cost;
2. define worker compute duration as `prefill + decode + recompute`;
3. enqueue that duration through the existing `ResourceModel.enqueue_task(...)`;
4. return both the scheduled resource task and the complete validated cost estimate.

Transfer time and state bytes remain explicit outputs for higher-level orchestration. This
prevents double-counting transfer and preserves the existing resource/network contract.

## 6. Dependency boundary

`pyproject.toml` continues to declare no mandatory runtime dependencies.

The C6.4g runtime module uses only the Python standard library plus existing CADI simulator
modules. CI imports the runtime under `python -S`, which disables site-package loading, and
then runs the targeted contract tests with pytest. NumPy/scikit-learn/Vidur are neither
installed nor needed by the C6.4g workflow.

The pinned numerical substrate remains relevant to reproducing C6.4f itself, but not to
ordinary lookup-based execution after C6.4f acceptance.

## 7. Non-claims

C6.4g does not claim:

- direct A100/H100 hardware calibration;
- accuracy beyond the pinned Vidur source model;
- prefill validity above 4,096 input tokens;
- transfer validity above predictor key 4,096 or at non-8,192-byte-aligned sizes;
- a new untouched holdout;
- a repaired C6.4c boundary;
- any new timing observation.

C6.4c remains permanently
`INVALIDATED_BY_SUPERSEDED_PREDICTOR_MATERIALIZATION`.

## 8. Exit criterion

C6.4g passes when the exact-head implementation demonstrates all of the following:

1. exact accepted C6.4f artifact identity is required before runtime projection;
2. both hardware runtime tables contain the complete accepted 4,096-axis families;
3. request-time mechanics match the frozen v4 contract for prefill, decode, recompute,
   transfer, state, and memory;
4. malformed provenance and out-of-domain requests fail closed;
5. validated compute can be scheduled through `ResourceModel` without modifying generic
   network semantics;
6. ordinary runtime import and execution require no third-party scientific dependency;
7. no new timing/calibration/source-model evaluation is performed.
