# 1. Research boundary

C4.5a begins S4 Evidence Safety without changing C1, C2, C3, baseline information privileges, or the C4.1 correctness schema before the closed stack is measured.

The canonical rule is:

```text
correctness-sensitive semantic commit
=> sufficient action-scoped Evidence

AMBIGUOUS Evidence / reconciliation
=> no semantic success
```

Evidence dimensions remain independent:

```text
Authority  ESTIMATED < DERIVED < EXACT_OBSERVATION < AUTHORITATIVE
Status     VALID | STALE | UNKNOWN | FAILED | AMBIGUOUS
Freshness  valid_until plus action-specific age rules
Scope      explicit semantic subject/action claims
```

---

# 2. Semantic action under test

The deterministic corpus uses request finalization as the correctness-sensitive commit surface.

Closed C1 requires:

```text
CURRENT Attempt
successful terminal Output
EXACT_OBSERVATION-or-higher Evidence
VALID Evidence status
Attempt-scoped Evidence
unexpired Evidence
```

The finalization transition is authoritative:

```text
Request -> COMPLETED
Attempt authority -> COMMITTED
CommittedAttempt -> current Attempt
AuthoritativeOutput -> terminal Output
```

The experiment preserves:

```text
Evidence objects
!= reconciliation outcome
!= policy-visible projection
!= authoritative finalize_request outcome
!= operation-level semantic result
```

# 3. Baseline fairness

All B0–B4 retain the same closed C1 `finalize_request(...)` semantic authority.

The frozen C3 information contract gives Evidence authority/status/freshness/reconciliation fields to B4 but not B0–B3. That information difference is recorded, but C4.5a does not bypass common C1 finalization for weaker baselines.

If the shared C1 guard yields identical authoritative correctness, the result is a semantic null comparator. If the shared C1 guard itself violates S4, the defect is recorded for all affected policies rather than being attributed to a baseline-information difference.

# 4. Deterministic corpus

The corpus contains ten scenarios:

```text
S4-AMBIGUOUS-ONLY
S4-VALID-PLUS-AMBIGUOUS-SAME-SCOPE
S4-STALE-ONLY
S4-UNKNOWN-ONLY
S4-FAILED-ONLY
S4-ESTIMATED-ONLY
S4-DERIVED-ONLY
S4-WRONG-SCOPE
S4-EXPIRED-VALID-UNTIL
S4-VALID-EXACT-CONTROL
```

Nine are faulted and provide one fixed exogenous paired ACR EventID each. The valid exact control is non-faulted.

---

# 5. Mandatory mixed-ambiguity probe

`S4-VALID-PLUS-AMBIGUOUS-SAME-SCOPE` supplies two Evidence objects for the same finalization scope:

```text
E1  EXACT_OBSERVATION / VALID / attempt a1
E2  EXACT_OBSERVATION / AMBIGUOUS / attempt a1
```

The independent oracle requires:

```text
reconcile(finalize, {E1,E2}) = AMBIGUOUS
semantic finalization allowed = false
```

This case is deliberately not reduced to “is there at least one sufficient Evidence item?”. The S4 invariant is that unresolved ambiguity relevant to a correctness-sensitive commit cannot silently become semantic success.

The harness executes the real closed C1 reconciliation and finalization paths separately. If reconciliation is `AMBIGUOUS` but finalization still commits, the classifier records a real ACR violation and O4 outcome.

No C1 repair is made before that evidence is captured.

# 6. Other Evidence faults

## Status

```text
AMBIGUOUS-only -> AMBIGUOUS, no commit
STALE-only     -> WAIT, no commit
UNKNOWN-only   -> WAIT, no commit
FAILED-only    -> WAIT, no commit
```

## Authority

```text
ESTIMATED-only -> below finalize minimum, WAIT
DERIVED-only   -> below finalize minimum, WAIT
```

The DERIVED fixture includes an explicit valid support Evidence ID and derivation rule. The Output references only the DERIVED Evidence so supporting authority cannot be smuggled into the semantic action.

## Scope

An otherwise valid `EXACT_OBSERVATION` scoped to a different Attempt must not satisfy finalization.

## Freshness

An otherwise valid `EXACT_OBSERVATION` with `valid_until < now` must not satisfy finalization.

## Positive control

A current, correctly scoped `EXACT_OBSERVATION / VALID` Evidence item must produce `MATCHED` reconciliation and normal authoritative finalization.

# 7. Independent oracle

Every faulted manifest declares before policy execution:

```text
semantic_commit_allowed = false
expected reconciliation outcome
fixed ACR EventID
fault class
```

The positive control declares `semantic_commit_allowed = true`.

The classifier compares authoritative post-finalization Request/Attempt state with the manifest. It does not ask the policy whether finalization should be considered correct.

---

# 8. Metric contract

## ACR

The nine faulted scenarios provide nine exogenous paired ACR opportunities per policy.

```text
ACR = ambiguous/non-committable authoritative commits
      / Evidence-fault commit opportunities
```

A violation requires actual authoritative semantic success when the independent oracle declares the Evidence state non-committable.

Explicit `AMBIGUOUS`, `WAIT`, `REJECT`, or `FAIL` without authoritative commit is not ACR.

## SSER

The same nine faulted operations form the SSER denominator. Any ACR semantic success is also an O4 silent semantic violation.

---

# 9. Policy-visible Evidence

A `PolicyObservation` is constructed from the same Evidence/reconciliation state for every baseline and projected through the frozen information contracts.

Expected visibility:

```text
B0-B3  no Evidence authority/status/freshness/reconciliation fields
B4     Evidence authority/status/freshness + reconciliation
```

This visibility is diagnostic in C4.5a. It does not replace C1 semantic authority.

---

# 10. Anti-false-zero requirement

A private regression hook runs the real C1 rejection path first, then forcibly installs authoritative finalization state for a non-committable case.

The classifier must then record:

```text
ACR violation = yes
O4 = yes
```

The corruption hook validates the measurement path only.

---

# 11. Candidate decision rule

The desired safety result is:

```text
ACR = 0
SSER = 0
```

for B4 and any competent baseline sharing the closed C1 semantic guard.

However, C4.5a is explicitly permitted to expose a closed-stack defect. If the mandatory mixed-ambiguity probe produces:

```text
reconciliation = AMBIGUOUS
finalize_request = authoritative success
```

then C4.5a must record nonzero ACR/O4, stop the normal merge/closure path, and open a repair gate. The result must not be hidden by changing the oracle, deleting the mixed case, weakening the ambiguity rule, or silently patching C1 before the failing evidence is preserved.

---

# 12. Exit criterion

C4.5a may merge as a completed safety slice only after:

```text
10-case deterministic corpus is reproducible
9 exogenous paired ACR EventIDs are policy-invariant
mixed valid+ambiguous behavior is measured explicitly
reconciliation and finalization remain distinct evidence fields
all insufficient status/authority/scope/freshness cases fail closed
valid exact positive control commits normally
anti-false-zero injection produces ACR + O4
Python 3.11 / 3.12 / 3.13 CI is green on the exact candidate
bounded exact-head review finds no unresolved substantive issue
```

If the closed C1 stack exhibits ACR/O4, C4.5a enters a repair gate rather than closing normally.
