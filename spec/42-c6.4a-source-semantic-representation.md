## Why a representation revision is required

The initial C6.1 mechanics used one affine law for each major physical primitive:

```text
prefill  = fixed + slope * input_tokens
decode   = fixed + slope * aggregate_context_token_steps
transfer = latency + bytes / bandwidth
```

C6.3 falsified adequacy of that complete representation on the declared Vidur projection domain:

```text
cold prefill               inadmissible negative FIT intercept on A100 and H100
single-token decode        adequate on held-out C6.3 points
point-to-point transfer    inadequate under the frozen held-out oracle
multi-token decode         analytically inconsistent fixed-term composition
```

The result is preserved. C6.4a does not clip the negative prefill intercept, narrow the old validation domain, add transfer breakpoints from failed residuals, or change the adequacy threshold.

## Pinned source semantics

The source family remains:

```text

model       meta-llama/Llama-2-7b-hf

```

The representation revision is motivated by source mechanics, not by fitting a new arbitrary polynomial to C6.3 held-out error.

At the pinned Vidur commit:

- compute components are modeled separately from profiling data;
- prefill attention uses `kv_cache_size` and `prefill_chunk_size_squared`;
- decode attention uses batch size and KV-cache size;
- send/recv has its own source model over a derived message-size/token feature;
- the linear-regression implementation is a polynomial-feature pipeline;
- its default grid searches polynomial degree 1 through 5, bias inclusion, interaction-only behavior, and intercept behavior.

Thus a universal first-order request-level law is not part of the source contract.

## Representation v2

Frozen representation identifier:

```text
cadi.c6.cost-representation.v2.curves+decode-step-affine
```

The v2 representation makes the minimum changes required by the C6.3 scientific result.

### 1. Cold-prefill curve

For positive input-token count, prefill is represented by an empirical piecewise-linear curve:

```text
prefill_curve(input_tokens) -> seconds
```

A curve consists of source-backed knots:

```text
axis_value
seconds
source_point_id
source_partition = C6.3_FIT
provenance       = P-SRC2
```

Contract:

```text
strictly increasing unique positive axes
finite nonnegative knot times
linear interpolation only between adjacent knots
no extrapolation outside the knot domain
no implicit monotonicity correction
no smoothing
no coefficient clipping
no source-row deletion
```

Zero input tokens evaluate to zero as workload semantics. This does **not** create or claim a physical zero-token profiling observation.

### 2. Recompute

Recompute uses the same prefill curve over missing reusable-prefix work:

```text
recompute_tokens = input_tokens - reusable_prefix_tokens

recompute_seconds =
    0                                      if recompute_tokens == 0
    prefill_curve(recompute_tokens)        otherwise
```

There is no independent recomputation magic constant.

### 3. Decode primitive is preserved

The C6.3b single-token affine primitive passed the C6.3c held-out oracle on both selected hardware profiles. It is retained:

```text
decode_step(context_tokens)
    = decode_fixed_seconds_per_output_token
    + decode_seconds_per_context_token_step * context_tokens
```

The parameter name now states the fixed term's correct dimensional meaning explicitly: seconds per generated output token.

### 4. Multi-token decode composition is corrected

For `m > 0` output tokens from initial context `n`:

```text
decode_context_token_steps =
    m*n + m*(m-1)/2

decode_seconds =
    m * decode_fixed_seconds_per_output_token
    + decode_seconds_per_context_token_step
      * decode_context_token_steps
```

This is equivalent to summing the validated single-token primitive at contexts:

```text
n, n+1, ..., n+m-1
```

The change is mechanical/analytic. It does not refit the single-token coefficients and is labeled `ANALYTICALLY_DERIVED`, not GPU-measured evidence.

### 5. Point-to-point transfer curve

For positive transfer size, transfer cost is represented by another empirical piecewise-linear curve:

```text
transfer_curve(bytes) -> seconds
```

It has the same FIT-only provenance, interpolation, and no-extrapolation rules as the prefill curve.

A zero-byte State transfer evaluates to zero because no State payload transfer operation occurs. Positive transfer values outside the calibrated curve domain fail closed rather than extrapolating an unexplained bandwidth constant.

### 6. State memory mechanics are unchanged

C6.4a does not revise:

```text
state_bytes = state_fixed_bytes + state_bytes_per_token * state_tokens
memory_capacity_fraction = state_bytes / memory_capacity_bytes
```

Those parameters remain separately source-tagged under the C6.1 provenance contract. C6.3 did not test or falsify this part of the representation.

## FIT-only curve construction rule

C6.4b may create prefill/transfer knots only from the canonical C6.3 `FIT` point set.

The machine-readable contract rejects:

```text
C6.3 VALIDATION point used as a knot
unknown point ID used as a knot
partial FIT knot set
non-P-SRC2 knot provenance
```

The complete C6.3 FIT set is required so that later code cannot silently remove an inconvenient training point after seeing fresh results.

The old C6.3 `VALIDATION` partition remains historical diagnostic evidence only. It cannot become replacement-model training evidence or the new adequacy boundary.

## Why decode does not receive a new off-grid physical boundary in C6.4a

The single-token decode primitive is unchanged and already passed the frozen C6.3 held-out test. C6.4a changes only its **sequence composition**. The resulting sequence identity is algebraically determined by repeated application of that unchanged primitive.

Accordingly:

```text
single-token validation   carry forward C6.3 held-out evidence
sequence composition      ANALYTICALLY_DERIVED identity
```

C6.4a does not manufacture a new decode measurement merely to relabel previously observed source axes as fresh evidence.

## Anti-leakage invariants

The following are forbidden:

```text

old C6.3 held-out residual used to select a knot or breakpoint

```

The boundary may be superseded only by a later explicit reviewed slice that establishes a new untouched boundary before observing its values. A failed boundary cannot be edited in place.
