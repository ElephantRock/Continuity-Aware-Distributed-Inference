## Policy set

Exactly four retention policies are compared later:

```text
LRU
FIXED_TTL
SESSION_PINNING
LIFECYCLE_B4
```

All receive the same immutable State objects, byte sizes, semantic validity, reuse opportunities, event stream, normalized byte capacity, and Program realization. Correctness and the reuse denominator remain policy-independent.

## Lifecycle and validity

The G0 separation is preserved:

```text
Lifecycle -> retention policy
Validity  -> correctness / semantic reuse
```

State lifecycle is derived from live dependent Continuations, not the origin Continuation alone:

```text
ACTIVE       if any dependent is ACTIVE
WAITING      else if any dependent is WAITING
SPECULATIVE  else if any dependent is SPECULATIVE
TERMINAL     otherwise
```

C7.3a supports only the Paper-1 minimum dependent lifecycle set above and fails closed on CREATED/JOINING/ABANDONED during retention evaluation.

Ground-truth lifecycle is common harness state, but visibility is policy-specific. INVALID State release is common. LRU and fixed TTL do not receive lifecycle for retention ranking or terminal release. Session pinning receives only Session identity/live status. B4 receives StateLifecycle.

## Equal-time event order

```text
1  validity invalidation and common INVALID release
2  common Continuation/Session transitions and ground-truth lifecycle recomputation
3  policy-specific lifecycle or Session-end release
4  fixed-TTL expiry
5  reuse lookup and semantic-validity decision
6  successful reuse touch/accounting
7  State admission
8  capacity enforcement
9  residency interval checkpoint
```

This ordering is frozen before P2/P3 outcomes.

## LRU

LRU admits every valid produced State whose object size is not larger than capacity, without a lifecycle test. Successful reuse refreshes recency. Capacity pressure evicts by:

```text
last_touch_time_seconds
admission_ordinal
StateID
```

in ascending order. Terminal-but-valid State is not released merely because it is TERMINAL; it remains until ordinary eviction or Program end. Capacity is never overcommitted.

## Fixed TTL

The primary ordinary baseline is:

```text
5 seconds
```

Predeclared sensitivity:

```text
0.25
1
5
30
120 seconds
```

TTL is fixed from admission; reuse does not refresh it. Expiry at exact equality occurs before reuse. Unexpired capacity pressure uses the same deterministic LRU tie-break. Terminal-but-valid State is not lifecycle-released.

Every TTL is reported separately. A best-of-grid envelope may be shown only as an explicitly oracle-tuned sensitivity upper bound, never as the sole ordinary TTL baseline.

## Session pinning

All valid State belonging to a live Session is pinned until that Session has no live dependent Continuation. It receives SessionID and SessionLiveStatus, not B4 lifecycle classes. Pinned State is not evictable for ordinary pressure.

If required pinned bytes exceed normalized capacity, the policy/configuration is:

```text
CAPACITY_INFEASIBLE
```

Capacity is not enlarged and pinned State is not silently evicted.

## B4 lifecycle retention

Carry the closed B4 mapping:

```text
ACTIVE       priority 3  PROTECT
WAITING      priority 2  RETAIN
SPECULATIVE  priority 1  BEST_EFFORT
TERMINAL     priority 0  RELEASE
```

B4 capacity eviction chooses lower lifecycle priority first and the common LRU tie-break within a priority. ACTIVE/PROTECT State is not ordinarily evictable. If ACTIVE protected bytes alone exceed capacity, the configuration is `CAPACITY_INFEASIBLE`; no overcommit occurs.

## Capacity normalization

The frozen `cache_capacity_ratio` axis remains P-SRC4. For each immutable Program realization, before policy decisions:

```text
reference_working_set_bytes =
  max over event time of sum(State.size_bytes)
  for valid State with ground-truth lifecycle != TERMINAL

capacity_bytes =
  floor(cache_capacity_ratio * reference_working_set_bytes)
```

The reference is ground-truth experiment normalization, not policy-visible future information. It is identical across compared policies and must be positive.

State byte sizes are immutable workload inputs with explicit provenance. C7.3a uses the predeclared C7.1 reference design point `state_tokens=16` (P-SRC4). The accepted C6.4f State-memory mechanics carry `state_fixed_bytes=0` and `state_bytes_per_token=524288`, giving exactly `8388608` bytes per C7.3 reference State. That mapping remains `SIMULATED_SOURCE_MODEL_DERIVED_P_SRC2`, not direct hardware measurement. C7.3a introduces no new State-size sweep.

## Residency accounting

A classified residency interval starts at admission/re-admission or immediately after successful reuse. It ends at the next successful reuse, eviction, TTL expiry, policy release, invalidation, or Program end.

```text
ends in successful reuse -> useful byte-seconds
any other end            -> wasted byte-seconds
byte-seconds             = State.size_bytes * interval duration
```

Useful and wasted classes therefore partition classified resident byte-time under the frozen C7.1 metric definitions.

## Tool-return TTFT

The frozen C7.1 boundary remains:

```text
first generated-token completion
-
tool-return/resume eligibility
```

Modeled first-token service is required recompute-prefill plus the first carried C6.3 decode step. Queue/resource delay from resume eligibility to service start remains included. Positive decode context is required, consistent with the closed C6 domain. Full-decode duration may not substitute for first-token completion.
