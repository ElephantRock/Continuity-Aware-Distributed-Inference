# C6.2 — First defensible calibration source family

Status: candidate under issue #105 / umbrella #102.

Base: C6.1 closure main `a3a6d372fe6f1b80702d773419aad9ddaa922008`.

## Purpose

C6.2 freezes the first P-SRC2 physical profiling corpus that C6.3 may project into the C6.1 cost evaluator. This slice intentionally does **not** fit cost coefficients. The separation prevents a source-selection step from silently becoming a calibration result.

## Source selection

Selected upstream repository:

`microsoft/vidur`

Pinned commit:

`abae7f63aa857300f5cdc6f5e0d27860cd24721b`

Publication reference:

`Vidur: A Large-Scale Simulation Framework For LLM Inference`, MLSys 2024, arXiv:2405.05465.

License: MIT at the pinned repository commit.

Vidur's pinned README identifies the project as a high-fidelity LLM inference system simulator and lists `meta-llama/Llama-2-7b-hf` as supported on both A100 80GB DGX and H100 DGX. Its pinned profiling documentation states that compute profiling requires actual GPUs and that network profiling is measured separately for the concrete node/interconnect configuration. Its pinned device configuration records 80 GB total memory for both A100 and H100. This is sufficient for C6.2's **source-corpus** classification as P-SRC2; C6.3 must still quantify projection/validation error before CADI treats any fitted coefficient set as calibrated.

## Selected cross-device family

Hold model architecture fixed and vary the device/profile family:

```text
source_id                          model                         hardware    network
vidur-llama2-7b-a100-dgx-v1       meta-llama/Llama-2-7b-hf    A100 80GB   a100_dgx
vidur-llama2-7b-h100-dgx-v1       meta-llama/Llama-2-7b-hf    H100 80GB   h100_dgx
```

This gives C6.3 a useful cross-device pair without conflating model changes with device changes.

## Manifest contract

Each `CalibrationSourceManifest` records:

```text
source class = PUBLISHED_OR_VALIDATED_PROFILE
upstream repository
upstream commit
license
publication/methods references
model identity
hardware identity
network identity
exactly one artifact for each required source role
```

Required roles:

```text
MODEL_CONFIG
DEVICE_CONFIG
COMPUTE_ATTENTION
COMPUTE_MLP
NETWORK_ALL_REDUCE
NETWORK_SEND_RECV
```

Manifest serialization is canonical and SHA-256 fingerprinted. Frozen fingerprints:

```text
A100  2b43edc3d5e5b62337cb87da4431ccbf24a0eb36a1d3914e49d2ba126766a758
H100  631438ac078a01db212a005557f7fe74e4da8a03d87738afb83c9985a276b6d7
```

`assert_source_snapshot` fails closed if a validation/download workflow observes a missing, extra, or changed upstream blob.

## Scientific boundary

C6.2 establishes **source identity and source provenance**, not fitted cost-model accuracy. Specifically, it does not claim:

- that raw Vidur rows are CADI C6.1 linear coefficients;
- that CADI reproduces Vidur timing yet;
- any A100/H100 timing number as a CADI physical measurement;
- any transfer-bandwidth/latency scalar before C6.3 projection;
- H4, H5, or H7 efficiency superiority.

C6.3 must perform a deterministic projection/reference reproduction from these exact artifacts into the C6.1 representation and must report error/residuals. If the C6.1 representation is too weak to reproduce the selected source within an acceptable declared error budget, C6.3 must revise the representation or report the calibration as inadequate rather than hiding the mismatch.
