## C6-admissible source rule

Mooncake source rows are retained for source-backed EV2+EV3 timing only when the **unmodified** source-observed values satisfy:

```text
input_tokens >= 1
output_tokens >= 1
input_tokens + output_tokens <= 4096
```

C7 may not clip, truncate, split, extrapolate, or otherwise alter source token counts to manufacture C6 coverage. The later source-backed C7 run must report retained/total rows and retained workload characteristics. That report is descriptive only and may not revise this predicate.

For synthetic controls, `(0,0)` is admitted, prefill-only controls may use `1..4096` input tokens, and positive decode obeys the same positive-context / 4096-token C6 fence.

## Finite transfer rule

The accepted C6 v4 transfer lattice is finite:

```text
8192 bytes per predictor token
predictor tokens 1..4096
maximum 33,554,432 bytes
State scalar 524288 bytes/State-token
```

C7 P5 P-SRC2 transfer evaluation uses exactly:

```text
state_tokens = {1,4,16,64}
```

These map to accepted transfer points without implicit chunking or extrapolation.

### Review correction R1 — exact P5 transfer points

The first C7.1 implementation accepted every State size `<= 64` tokens. That was broader than issue #135, which predeclared exactly `{1,4,16,64}`. Review tightened `validated_transfer_state_admissible` to exact membership and added executable byte/lattice checks.

No C6 evidence changed.

## Parameter-source classification

C7 distinguishes **the source of an experiment-axis value** from **the source of the cost function used to evaluate that value**.

All predeclared C7.1 sweep axes are synthetic design points and therefore:

```text
P-SRC4
```

unless a later manifest value is directly source-observed/trace-derived and explicitly classified accordingly.

The C6 runtime used to evaluate in-domain costs remains:

```text
P-SRC2 source-model-derived evidence
```

### Review correction R2 — sweep points are not calibration evidence

The first implementation labeled the P5 `state_tokens` and `recompute_tokens` axes P-SRC2 merely because their costs are evaluated by the C6 P-SRC2 model. Review rejected that conflation. The axis choices are now P-SRC4; only the C6 cost projection retains P-SRC2 classification.

This prevents synthetic experimental design choices from being promoted into empirical/calibration facts.

## Metric semantics

C7.1 freezes executable definitions for:

```text
Recomputation Ratio
State Reuse Ratio
State Reuse Token Ratio
Useful State Residency
Wasted State Residency
Cold Continuation Rate
State Transfer Volume
Program Completion Time
Tool-Return TTFT
Fan-Out Completion Time
Recovery Time
```

The normalized definitions are machine-readable in `METRIC_DEFINITIONS`.

### Recomputation Ratio

```text
numerator
eligible reusable prefix tokens not consumed and therefore recomputed

denominator
sum of source/control input tokens across the same inference opportunities
```

The denominator is intentionally policy-independent for paired comparisons.

### State Reuse Ratio

```text
eligible State reuse opportunities actually consumed
/
eligible State reuse opportunities
```

### State Reuse Token Ratio

```text
eligible reusable prefix tokens actually consumed
/
eligible reusable prefix tokens
```

### Useful / Wasted State Residency

Residency is byte-time weighted:

```text
useful byte-seconds
/
total classified resident byte-seconds

wasted byte-seconds
/
total classified resident byte-seconds
```

A residency interval is useful iff the retained State is reused before the interval ends. Otherwise its resident byte-time is wasted for this metric.

### Cold Continuation Rate

```text
reuse-eligible continuation executions consuming zero reusable prefix tokens
/
reuse-eligible continuation executions
```

Timing metrics use explicit start/end event definitions and fail closed if end precedes start.

## Semantic validity before performance ranking

C7 does not permit semantic failure to masquerade as speedup.

For every policy/configuration, covered C4/C1 correctness counters are retained beside efficiency outputs. If any covered semantic violation occurs, the point is labeled:

```text
SEMANTICALLY_INVALID_FOR_EFFICIENCY_RANKING
```

Its timing may remain as diagnostic data, but it is excluded from any performance-superiority claim.

## Paired fairness rule

Compared policies must receive the same underlying:

```text
source segment / synthetic workload
augmentation seed
resource configuration
fault schedule
```

while each policy receives only information permitted by its closed C3 information contract.

A run violating paired fairness is invalid for C7 comparison.

## Statistical procedure

Common random numbers are mandatory for paired stochastic comparisons.

Fixed stochastic seed sequence:

```text
0..63
```

Consumed only in prefixes:

```text
8
16
32
64
```

Convergence checks occur only at those prefixes. Seeds are never skipped/replaced based on observed results.

Targets:

```text
proportions
95% interval half-width <= 0.01 absolute

continuous paired differences
95% interval half-width <= 5% of corresponding nonzero baseline median magnitude
```

If a point has not converged at 64 runs, it is reported as uncertainty-limited with its 64-run interval. C7 does not extend it opportunistically.

Paired nonparametric bootstrap:

```text
resamples      10000
RNG seed       20260911
interval       percentile 95%
cluster unit   Program; Session only when Program is not the independent unit
```

Deterministic fixed-source runs are not padded with artificial replication.

## Invalid-result conditions

A C7 result is invalid for efficiency comparison if any of the following occurs:

```text
source row clipped/truncated/extrapolated into C6 domain
positive decode escapes C6 finite model-length domain
P-SRC2 transfer uses State size outside {1,4,16,64}
paired policies do not share workload/resource/fault realization
policy receives undeclared information
covered semantic violation counted as a performance win
synthetic parameter relabeled as empirical evidence
observed comparative result changes this protocol in place
```

A necessary protocol revision creates a new protocol version and preserves the old result; it does not overwrite C7.1.
