# 1. Research boundary

C4.4c is the final bounded S3 correctness slice. It validates the closed C4.4a/C4.4b Binding-safety semantics under measured real-process execution without changing C1, C2, C3, the baseline information contracts, or the C4.1 correctness schema.

The canonical safety rule remains:

```text
ownership-sensitive commit(y, e) => e == CurrentEpoch(y)
```

Safe migration additionally requires sufficient Evidence and one semantic transition of:

```text
(CurrentEpoch, ActiveBinding)
```

The primary invariant families remain D1–D5, F3, and Composite Safe Migration.

# 2. EV1 execution contract

The EV1 harness uses bounded real worker processes rather than simulated workers.

Per scenario it creates three `spawn`-based processes:

```text
w1
w2
w3
```

Each process has its own PID and process-local physical Binding map. Communication uses real `multiprocessing.Pipe` IPC.

Workers may execute these physical operations:

```text
RESET
ARM_MATERIALIZE
GO_MATERIALIZE
DROP
CPU
PRESENT
CRASH
STOP
```

Materialization and delayed-work operations execute real SHA-256 CPU work and record:

```text
worker PID
wall start/completion timestamps
process CPU seconds
wall execution seconds
CPU digest
physical BindingID / epoch / completeness
```

Worker processes never mutate C1 semantic state. The coordinator alone owns the `ContinuityCore` instance and performs authoritative Binding proposals, migrations, Evidence recording, and commit attempts.

# 3. Measurement boundary

C4.4c preserves the established five-stage distinction:

```text
physical transfer/materialization observation
!= policy migration admission
!= authoritative C1 migration commit
!= stale/conflicting owner presentation
!= operation-level semantic result
```

A physical process retaining a Binding, a destination completing CPU work, a B4 `ALLOW_COMMIT`, or a late stale presentation is not itself semantic ownership.

Authoritative Binding state remains defined only by C1:

```text
current_binding_by_subject
current_epoch_by_subject
Binding.status
```

SBDR is classified after the measured physical presentation has reached the real C1 commit path.

# 5. Mandatory measured corpus

The corpus contains seven scenarios:

```text
E1-S3-A-PARTIAL-MATERIALIZATION
E1-S3-B-DESTINATION-CRASH
E1-S3-C-LATE-OLD-OWNER
E1-S3-D-CONCURRENT-CANDIDATES
E1-S3-E-DELAYED-STALE-LOSER
E1-S3-F-MULTI-EPOCH-LATE-OWNER
E1-S3-G-SUCCESS-CONTROL
```

Six scenarios are faulted and carry one fixed exogenous paired SBDR EventID each. The success control is non-faulted.

## 5.1 Partial materialization

`b2 / epoch 2` is physically materialized on W2 with completeness `PARTIAL`, but no semantic commit Evidence exists.

Measured behavior:

```text
physical b2 exists on W2
B4 admission = WAIT
C1 commit attempt = rejected for insufficient Evidence
final authority = b1 / epoch 1
outcome = O3
```

Physical destination presence is therefore insufficient to establish Binding authority.

## 5.2 Destination crash before commit

`b2 / epoch 2` is fully materialized on W2. W2 then exits through a real process crash path before any semantic commit Evidence is supplied.

The harness requires the process to terminate with the fixed non-zero crash exit code.

Measured behavior:

```text
W2 process exit is measured
no destination presentation is fabricated after exit
C1 commit attempt = rejected for insufficient Evidence
final authority = b1 / epoch 1
outcome = O3
```

## 5.3 Late old owner after successful migration

W2 physically materializes `b2 / epoch 2`; measured Evidence permits the coordinator to commit W1 -> W2. W1 still physically retains `b1 / epoch 1` and later presents it.

Measured behavior:

```text
b2 / epoch 2 remains authoritative
late b1 presentation reaches C1
C1 rejects stale old-owner commit
outcome = O1
```

## 5.4 Concurrent candidates

W2 and W3 concurrently materialize:

```text
b2 / epoch 2 / base 1
b3 / epoch 3 / base 1
```

Both physical materializations are measured before the semantic winner is chosen. `b2` commits first. W3 later presents `b3` with otherwise valid measured Evidence.

Measured behavior:

```text
one semantic winner only
b2 / epoch 2 remains authoritative
b3 stale-base presentation is rejected
outcome = O1
```

## 5.5 Delayed stale loser

W2/W3 again create concurrent physical candidates. W3 performs additional real CPU work after the race has begun while W2 wins the semantic commit. The delayed W3 stale presentation is then delivered.

Measured behavior:

```text
real stale-loser CPU work is measured
b2 / epoch 2 remains authoritative
b3 presentation is fenced
outcome = O1
```

## 5.6 Multi-epoch late owner

Measured sequential migrations commit:

```text
W1/b1/epoch1 -> W2/b2/epoch2 -> W3/b3/epoch3
```

W1 then physically presents retained `b1 / epoch 1`.

Measured behavior:

```text
b3 / epoch 3 remains authoritative
multi-epoch old-owner presentation is rejected
outcome = O1
```

## 5.7 Success control

W2 physically materializes a valid next-epoch candidate and presents it with measured `EXACT_OBSERVATION` Evidence.

Measured behavior:

```text
b1 / epoch 1 -> SUPERSEDED
b2 / epoch 2 -> ACTIVE
CurrentEpoch = 2
outcome = O1
```

This proves the EV1 safety result is not obtained by globally disabling migration.

# 6. Independent oracle and Evidence

Every scenario declares before policy execution:

```text
expected final BindingID
expected final epoch
fault class
SBDR EventID
explicit-WAIT expectation
```

The oracle does not ask a policy whether the Binding is current.

Measured commit Evidence is created only from actual worker-process events and is scoped to:

```text
BindingID
epoch
worker ID
worker PID
```

The C1 semantic requirement remains the BindingID/epoch subset. Worker identity is retained as additional measurement provenance.

Setup migration commits are recorded separately from the final stale/conflicting presentation so a setup failure cannot be silently attributed to the denominator event.

# 7. Metric contract and measured outcome partition

## SBDR

The six faulted scenarios provide six fixed exogenous paired opportunities per policy.

```text
SBDR = authoritative Binding divergences / Binding-sensitive opportunities
```

A violation requires actual post-presentation authoritative divergence from the predeclared BindingID/epoch pair.

Rejected, failed, or WAITed commit attempts are not SBDR violations.

## SSER

The same six faulted operations form the SSER denominator.

Measured faulted outcome partition under the closed C1 authority:

```text
O1  4
O2  0
O3  2
O4  0
```

The O3 cases are partial materialization and destination crash before semantic commit.

# 10. H6/S3 adjudication

C4.4a, C4.4b, and C4.4c all produce zero B4 SBDR and zero B4 SSER for their covered Binding-safety faults. C4.4c satisfies the required EV1 condition with real processes, IPC, CPU work, process failure, and stale physical owner presentations.

All three slices also remain semantic null comparators across competent B0–B4 because the shared closed C1 commit guard implements the semantic Binding-authority mechanism.

The supported correctness claim is therefore:

> Explicit Binding epochs, stale-binding fencing, sufficient Evidence, and one semantic migration commit point prevent silent Binding divergence under the covered migration/failover races.

The stronger B4-specific comparator claim is not supported:

> B4 uniquely improves semantic Binding correctness over competent baselines that are already constrained by the same C1 Binding-authority mechanism.

That stronger claim is narrowed rather than manufactured by weakening baseline semantics. B4-specific advantages remain available for later efficiency, observability, reconciliation, and placement questions where its additional Continuity information can produce real distinctions.
