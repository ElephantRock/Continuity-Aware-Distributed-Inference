C5.4 integrates the three workload classes required by the C5 exit criterion while preserving their provenance boundaries.

## Explicit workload modes

The canonical mode enum is:

```text
SOURCE_DERIVED
TRACE_AUGMENTED
FULLY_SYNTHETIC
```

Mode is always explicit. It is not inferred from whichever optional artifact happens to be supplied.

A `WorkloadEnvelope` is a canonical provenance descriptor containing:

```text
schema
mode
source_dataset_fingerprint
augmentation_fingerprint
augmentation_source_dataset_fingerprint
synthetic_dataset_fingerprint
```

All mode-specific fields are present in canonical JSON; inapplicable fields are explicit nulls.

## Source-derived and trace-augmented modes

`SOURCE_DERIVED` requires exactly one C5.1 `NormalizedTraceDataset` fingerprint and forbids augmentation/synthetic artifact fingerprints. `WorkloadEnvelope.source_derived()` records the exact source fingerprint and `assert_matches_source()` revalidates it without rewriting source JSON.

`TRACE_AUGMENTED` requires one `NormalizedTraceDataset` plus one C5.3 `ContinuityAugmentationDataset` and forbids a fully synthetic dataset. Construction calls C5.3 `assert_compatible_source()` first. The envelope stores the source fingerprint, augmentation fingerprint, and the augmentation's bound source fingerprint, and requires the two source fingerprints to match. Neither input artifact is modified.

## Fully synthetic mode

`FULLY_SYNTHETIC` requires one dedicated `FullySyntheticWorkloadDataset` fingerprint and forbids public/source-derived and trace-augmentation fields.

The fully synthetic artifact is deliberately not represented as a C5.1 `NormalizedTraceDataset`. It therefore does not carry a `TraceSourceManifest`, public source URI, public license metadata, public source checksum, `SOURCE_OBSERVED`, or `TRACE_DERIVED` provenance. Its only provenance is `SYNTHETIC`.

Schema:

```text
schema       cadi.c5.4.fully-synthetic-workload.v1
version      cadi.c5.4.fully-synthetic-workload.v1
provenance   SYNTHETIC
config       complete deterministic generator configuration
records      complete synthetic workload records
```

Each record contains `record_id`, `ordinal`, `arrival_time_s`, `input_tokens`, `output_tokens`, `prefix_group_id`, and `prefix_tokens`; all are synthetic.

## Generator configuration

The explicit generator configuration contains:

```text
seed
request_count
interarrival_s_choices
input_tokens_choices
output_tokens_choices
prefix_fraction_choices
prefix_group_count
```

Validation rules: seed is a nonnegative integer; request count is positive; interarrival choices are unique finite positive values; input-token choices are unique positive integers; output-token choices are unique nonnegative integers; prefix fractions are unique finite values in `[0,1]`; all choice arrays are nonempty; prefix group count is nonnegative; and any positive prefix fraction requires a positive prefix group count.

These are control parameters only. No choice set is described as realistic or representative without later empirical justification.

## Deterministic construction

The generator does not use process-global RNG state or Python `random`.

Each choice hashes the unit-separator joined UTF-8 tuple `seed`, synthetic `record_id`, and decision `channel` with SHA-256 and maps the first eight digest bytes to a configured choice index. Channels are `interarrival`, `input-tokens`, `output-tokens`, `prefix-fraction`, and `prefix-group`.

For ordinal `i`:

```text
record_id
  synthetic:{i:06d}

arrival_time_s
  0.0 for i = 0
  prior arrival + deterministic configured interarrival otherwise

input_tokens / output_tokens
  deterministic configured choices

prefix_tokens
  floor(input_tokens * deterministic configured prefix fraction)

prefix_group_id
  null when prefix_tokens = 0
  synthetic-prefix:{group:04d} otherwise
```

The dataset validates contiguous ordinals, canonical IDs, first arrival zero, strictly increasing later arrivals, token choices admitted by configuration, configured synthetic prefix groups, bounded prefixes, and a prefix length admitted by at least one configured fraction. `assert_reproducible()` regenerates the entire dataset from config/seed and requires byte-identical canonical JSON.

  d78dbb41571aec557c2a6fc581e454a0cd50011b8f3582bcaa9eaa1c495c4051

This vector proves deterministic mechanics, not an empirical workload result.

## Canonical serialization and mode matrix

Both the fully synthetic dataset and workload envelope use sorted compact JSON, explicit nulls, `allow_nan=False`, and SHA-256 over canonical UTF-8 JSON. Parsing rejects duplicate JSON members, non-finite constants, unknown/missing schema members, unsupported schema/version, invalid provenance or workload mode, malformed fingerprints, and illegal cross-mode artifact combinations.

```text
SOURCE_DERIVED
  source     required
  augment    forbidden
  synthetic  forbidden

TRACE_AUGMENTED
  source     required
  augment    required and source-compatible
  synthetic  forbidden

FULLY_SYNTHETIC
  source     forbidden
  augment    forbidden
  synthetic  required and reproducible
```

A serialized `TRACE_AUGMENTED` envelope repeats the augmentation's source fingerprint and requires equality with the source dataset fingerprint, preserving compatibility evidence even when only the descriptor is inspected.

## Deterministic tests

C5.4 tests cover the frozen replay vector; same config/seed replay; process-RNG independence; semantic config sensitivity; dictionary-order independence; arrival/token/prefix invariants; zero/positive-prefix controls; configuration validation; canonical synthetic round trip; semantic tamper detection; synthetic/source schema separation; all three mode constructors; source/augmentation immutability; trace source-compatibility; illegal cross-mode combinations; explicit serialized mode; artifact match checks; and malformed synthetic/envelope JSON rejection.

## Claim boundary

C5.4 supports explicit construction/distinction of source-derived, trace-augmented, and fully synthetic workloads with end-to-end fingerprints and deterministic synthetic replay. It does not establish that the synthetic control is representative of production, physical inference or KV-transfer cost, cache-retention probability, or H4/H5/H7 efficiency superiority.
