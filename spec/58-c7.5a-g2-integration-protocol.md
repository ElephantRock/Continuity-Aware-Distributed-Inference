## Trace-augmented source realization

C7.5b uses `TRACE_AUGMENTED` Programs.

Source token lengths come from the exact C7-admissible Mooncake subset. Synthetic augmentation supplies only structure unavailable in the trace: Continuation/session/fan-out structure plus controlled resource/locality facts.

The 64 source rows are selected before any comparative result by:

1. retaining only rows already inside the C7.1/C6 token domain;
2. additionally requiring `input_tokens % 4 == 0` so exact quarter-step reuse fractions require no rounding;
3. sorting by `SHA256(cadi.c7.5a.seed-record.v1|record_id)`, then `record_id`;
4. mapping seeds `0..63` to the first 64 unique rows in that order.

No source field is clipped, truncated, rounded, or mutated.

The exact selected mapping is frozen by:

```text
schema
cadi.c7.5a.seed-source-selection.v1

selection fingerprint
bebaf2e535b78177cb3ef2c39fddd9e23180c4aecb3e06deac9390d29b190fe4
```

The fingerprint binds the admissible-dataset fingerprint, selected count, ordered record IDs, input tokens, and output tokens. C7.5b must reproduce this identity from the pinned source rather than merely trust a stored list.

Resource facts are domain-separated SHA-256 functions of the frozen seed. Worker queue depth, physical State location, and session-preferred location use distinct labels. P4 branch-load facts also include branch ordinal so fan-out branches are not forced to receive identical load observations. Worker-count helpers fail closed outside the frozen `{2,4,8}` domain; P4 locality/load helpers are fixed to the reference worker count `4`.

## H4 — State reuse / recomputation

Primary metric:

```text
Recomputation Ratio
```

Primary comparators:

```text
B0 request-centric
B1 cache-aware
B2 session-affinity
```

B3 is diagnostic.

Support is evaluated per comparator, not by requiring a simultaneous win over every baseline. For one comparator, a P1 cell supports B4 only when:

- both rows are semantically eligible;
- the paired Program-cluster 95% bootstrap interval for `RR(B4)-RR(baseline)` is entirely below zero;
- the non-timing RR result is identical across accepted A100/H100 source-model strata.

A meaningful region requires an orthogonally connected component of at least two support cells within one fixed-worker-count P1 surface for the same comparator.

H4 is supported if at least one primary comparator has such a region. The result must still report every B0/B1/B2 support map, tie, loss, and no-benefit region.

This is deliberately consistent with the canonical H4 criterion: improvement versus relevant baselines, uncertainty support, persistence beyond one isolated point, and no semantic regression. It does not require universal dominance.

### B1 confluence limitation

C7.2 may make B1 and B4 select the same worker whenever both can use the same compatible resident State locality. Therefore a B1 tie is a legitimate no-benefit region. C7.5 may not weaken or remove B1 to manufacture H4 support.

## H7 — Program-level statefulness gradient

The reference policy is frozen to B0 before result inspection.

```text
P1 benefit = (PCT_B0 - PCT_B4) / PCT_B0
P4 benefit = (FCT_B0 - FCT_B4) / FCT_B0
```

Eligible statefulness axes:

```text
P1: session_depth, reusable_prefix_fraction
P4: fanout_width, shared_prefix_fraction
```

A qualifying gradient is an axis-aligned contiguous run at fixed other-axis value, and fixed worker-count stratum for P1, satisfying:

- at least three ordered axis levels;
- every cell has a paired 95% benefit interval entirely above zero;
- median per-Program paired benefit is nondecreasing across the run;
- at least one adjacent level increases strictly;
- the same directional gradient appears on both accepted C6 source-model hardware strata.

H7 is supported when at least one qualifying P1 or P4 gradient exists and P7 passes. Qualifying gradients on both P1 and P4 are stronger cross-dimension confirmation, not a mandatory criterion. Non-monotone dimensions remain reportable interactions; H7 does not require every variable to be monotonic.

## P7 negative control

P7 is not ranked as efficiency support. It passes only when every policy has:

```text
State Reuse Ratio = 0
Recomputation Ratio = 0
identical modeled Program Completion Time
```

for every worker-count cell and both C6 source-model hardware strata.

Routing/control duration remains `ZERO_UNEVIDENCED_COMPONENT`. Therefore P7 is not evidence that physical software-control overhead is zero.

## Information-contract decomposition

B0–B4 remains an information-contract ladder, not a pure one-factor causal ablation. B4-vs-B3 is diagnostic unless a closed targeted experiment independently isolates the relevant mechanism.

This matters because C7.5 must not over-attribute an observed B4 difference to a single field when multiple information dimensions differ between contracts.

## Gate G2

C7.5b must classify exactly one:

```text
G2_A_STRONG_EFFICIENCY_SUPPORT
G2_B_MEANINGFUL_FRONTIER_OR_STATEFULNESS_THRESHOLD
G2_C_NO_USEFUL_SYSTEMS_LEVERAGE
```

Decision order:

1. A if H7 is supported and at least two of H4/H5/H6 are supported or strengthened within their declared phase spaces;
2. C if none of H4/H5/H6/H7 has a qualifying meaningful region;
3. B otherwise.

This preserves the North Star Gate G2 requirement: useful systems leverage requires at least one meaningful region, not universal superiority.

## Pre-result bounded-review corrections

All corrections below occurred before any C7.5 comparative result was executed or inspected.

The first draft imposed two stronger scientific rules than the canonical research documents:

- H4 required B4 to beat B0, B1, and B2 simultaneously;
- H7 required qualifying gradients in both P1 and P4.

Review rejected both. The final freeze uses per-comparator H4 regions and one-or-more statefulness dimensions for H7, while requiring all baseline/no-benefit regions to remain visible.

A second mechanics/provenance review found two additional issues:

- the initial CI source-selection “reproduction” copied the first generated JSON before comparing it rather than independently deriving the selection twice;
- the future `TRACE_AUGMENTED` manifest's augmentation-fingerprint semantics were not yet frozen.

The workflow now derives the source selection independently twice from the pinned Mooncake source, and the augmentation fingerprint is specified by the schema above.
