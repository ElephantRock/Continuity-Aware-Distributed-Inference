## Program realization

C7.5b consumes the exact `TRACE_AUGMENTED` realization frozen by C7.5a.

### P1 Deep Continuation Reuse

For each selected source row, seed, and frozen P1 cell:

- every operation preserves the source row's exact input/output token counts;
- Program depth equals `session_depth`;
- the root has zero reuse opportunity and no fabricated State locality;
- each later operation has exact reusable tokens equal to `input_tokens × reusable_prefix_fraction`;
- each reuse-eligible continuation receives one seed/ordinal-derived physical State location;
- session-preferred location is independently seed-derived;
- each worker's queue-depth fact is independently seed/worker/operation-derived;
- all semantic control facts presented to B4 are valid/current/matched.

The independent semantic oracle also marks the constructed attempts current and States compatible. Any semantic violation in the paired result is therefore an implementation defect, not an intended workload outcome.

### P4 Fan-Out Shared Prefix

For each selected source row, seed, and frozen P4 cell:

- every branch preserves the same exact source token pair;
- branch count equals `fanout_width`;
- every branch has the exact `shared_prefix_fraction` reuse opportunity;
- all branches refer to one shared exact State with one seed-derived physical location;
- branch load facts are branch-specific;
- session-preferred location is independent of State location.

This construction deliberately preserves the possible tradeoff between locality/reuse and fan-out parallelism. It does not force B4 to win: concentrating shared State at one worker can serialize locality-seeking branches under the C7.2 resource-time model.

### P7 Stateless Control

Each P7 Program is exactly one source-shaped request with:

- zero reusable State opportunity;
- no State/candidate/location/provenance hints;
- no session-preferred location;
- no Binding/Evidence/lifecycle/reconciliation hints;
- only the frozen worker-count axis varied;
- nominal `arrival_intensity=1.0` retained only as a manifest parameter, not as a modeled arrival process.

All B0–B4 policies must therefore converge on zero State reuse, zero Recomputation Ratio, and equal modeled Program Completion Time within each hardware stratum.

## H4 estimator and region mechanics

H4 uses ratio-of-sums Recomputation Ratio exactly as frozen.

For each Program:

```text
RR numerator   = eligible_reuse_tokens - consumed_reuse_tokens
RR denominator = total_input_tokens
```

For every bootstrap resample, Program clusters are sampled by the already-frozen C7.1/C7.3 deterministic bootstrap schedule; B4 and baseline use the same sampled Program indices; each side's RR is recomputed from summed numerator/denominator components before taking `B4 - baseline`.

A support cell has a percentile-95 interval entirely below zero. Non-timing outcomes must be exactly invariant across the accepted A100/H100 source-model strata before the cell can participate in H4.

Connected H4 regions use the C7.5a orthogonal P1 adjacency and cannot cross worker-count strata.

## H7 estimator and gradient mechanics

For P1 and P4, one Program-level benefit is:

```text
(baseline_time - B4_time) / baseline_time
```

The cell point estimate and each bootstrap replicate use the ratio of summed paired Program times:

```text
(sum baseline - sum B4) / sum baseline
```

The bootstrap remains paired by Program. The separate trend point required by C7.5a is the median of the per-Program paired relative benefits.

A cell is favorable only when its percentile-95 interval is entirely above zero. Gradient detection then searches only axis-aligned contiguous runs of at least three frozen levels, holding every other surface coordinate fixed (and worker count fixed for P1). The median Program benefit must be nondecreasing with at least one strict increase **independently in both accepted hardware strata**.
