### Preliminary-probe prefix statistic exclusion

The initial source probe also printed exploratory prefix statistics using
independent `(position, hash_id)` membership. That check was sufficient for
source shape inspection but is weaker than the predeclared C5.2 oracle because
different prior requests could theoretically contribute different positions.

Those exploratory prefix numbers are therefore **not** C5.2 EV2 results and
are not used in the final report.

The actual adapter uses exact prior hash-sequence prefix paths, tested by a
counterexample in which position-wise membership would otherwise fabricate a
longer prefix.

## Upstream row contract

Every source JSONL line must contain exactly:

```text
timestamp
input_length
output_length
hash_ids
```

Rules:

```text
timestamp      nonnegative integer milliseconds
input_length   nonnegative integer token count
output_length  nonnegative integer token count
hash_ids       JSON array of nonnegative integers
```

Booleans are not integers for this contract. Unknown or missing members,
duplicate JSON object members, non-finite constants, malformed UTF-8, and
blank JSONL records fail closed.

## Normalization

For source ordinal `i`:

```text
record_id
  mooncake-fast25:{i:05d}

source_record_id
  jsonl-line:{i+1}

source_ordinal
  i

arrival_time_s
  timestamp / 1000

input_tokens
  input_length

output_tokens
  output_length
```

All three workload fields above are `SOURCE_OBSERVED`.

## Reusable-prefix derivation

Prefix fields are `TRACE_DERIVED`, not source-observed.

Maintain a trie containing exact hash-sequence prefixes from requests that
occurred earlier in source order. For the current request let `k` be the
longest leading hash sequence already represented by one prior sequence path.

Then:

```text
prefix_tokens
  min(input_length, 512 * k)

prefix_group_id
  null                                if k = 0
  mooncake-hash:{hash_ids[k - 1]}     if k > 0
```

This is explicitly an **online prior-source-order reuse opportunity**.

It does not assert:

```text
that a production cache retained the prefix
that a scheduler selected it
that a worker consumed it
that physical KV state was available
```

Those are later policy/resource questions.

### No cross-request position mixing

The derivation must not infer a prefix merely because every `(position,
hash_id)` has appeared somewhere previously. The entire path must exist in the
prior-prefix trie.

Required counterexample:

```text
prior A  [1, 2]
prior B  [1, 3, 4]
current  [1, 2, 4]

correct longest prior prefix
  [1, 2]
  k = 2

incorrect position-wise union
  could falsely infer k = 3
```

The C5.2 test suite locks this distinction.

## Full-source EV2 validation

`.github/workflows/c5-mooncake-source.yml` downloads the immutable source,
executes the same pinned adapter used by the experiment code, and records:

```text
raw SHA-256
raw byte count
request count
arrival range
input/output ranges and means
reusable-request count and fraction
prefix-token mean and maximum
C5.1 field coverage
normalized dataset fingerprint
```

The workflow also checks the independently measured source digest/count/ranges
before accepting the result.

The exact final EV2 summary is added to this specification only after the
candidate workflow executes. Do not substitute the preliminary probe's weaker
prefix statistic.

## Claim boundary

C5.2 may support:

```text
EV2 source provenance
real workload arrival/length distributions
source-derived reusable-prefix opportunity structure
deterministic normalized replay
```

C5.2 does not support:

```text
GPU timing
KV transfer cost
prefill/decode latency
production cache hit probability
policy efficiency superiority
synthetic session/branch semantics
```

Those remain later C5/C6/C7 work.

## Exit

C5.2 closes after:

1. the immutable source checksum is frozen;
2. adapter/unit tests pass in Python 3.11/3.12/3.13 CI;
3. the full pinned-source workflow executes successfully;
4. its exact EV2 summary and normalized fingerprint are recorded;
5. bounded exact-head technical/scientific review finds no source,
   normalization, or provenance blocker;
6. the reviewed exact head is SHA-fenced and squash-merged.
