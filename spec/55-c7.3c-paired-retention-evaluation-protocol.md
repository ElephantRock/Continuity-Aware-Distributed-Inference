## Common random numbers

Experiment stochasticity uses a counter-style SHA-256 uniform. Axis values are intentionally excluded from draw keys so neighboring surface points are coupled by common random numbers.

```text
P2 tool-return uniform
(schema, P2, seed, target, tool-return)

P2 pressure admission priority
(schema, P2, seed, pressure-state, admission-priority)

P3 speculative classification
(schema, P3, seed, branch-index, speculative-class)

P3 admission priority
(schema, P3, seed, branch-index, admission-priority)
```

Thus increasing tool-return probability thresholds the same uniform, changing tool gap rescales the same event realization, changing cache ratio changes capacity only, and shared branch indices retain the same classification/admission priorities as branch width grows.

Seeds are exactly `0..63`.

## P2 — tool-gap retention under controlled pressure

Each P2 Program contains one target State and three pressure States, each in a distinct Session. All use the frozen State size.

The target is admitted at Program time 0. At 10% of the tool-gap duration its live-dependent set becomes WAITING-only. The three pressure States are one ACTIVE and two SPECULATIVE; which pressure State is admitted earlier is determined only by the common seed-derived admission priorities. Their admission times are 25%, 50%, and 75% of the tool gap.

At the tool-return boundary, the common Bernoulli draw is thresholded by `tool_return_probability`:

```text
return
  waiting ancestor completes conceptually
  a new required child Continuation contributes an ACTIVE dependency
  State dependent-lifecycle set therefore becomes ACTIVE
  one semantically-valid reuse lookup follows

no return
  waiting dependency completes
  State dependent-lifecycle set becomes TERMINAL
  target Session ends
  no reuse opportunity
```

`DEPENDENTS` events encode the State's current live-dependent lifecycle set. They do not mean that one Continuation itself transitions WAITING -> ACTIVE. This preserves the G0 tool-gap lineage decision: tool return creates a child continuation while the waiting ancestor completes.

Pressure State and remaining Session cleanup occurs deterministically just after the return boundary. The peak common nonterminal reference working set is exactly four States, so C7.3a capacity normalization maps cache ratios 0.25/0.5/1/2 to one/two/four/eight State-equivalents.

This is a synthetic W3 plus W8 pressure construction, not an empirical tool-gap frequency model.

## P3 — branch/cache pressure

Each P3 Program contains exactly `branch_width` branch States in one Session. At the cache-pressure interval each branch has a causal future-use class:

```text
SPECULATIVE  if common per-branch uniform < speculative_fraction
WAITING      otherwise
```

Admission order is a separate seed-derived permutation and therefore does not encode lifecycle class. All branches are admitted before one common resolution boundary.

At resolution:

```text
WAITING
  required branch contributes a new ACTIVE continuation dependency
  State dependent-lifecycle set becomes ACTIVE
  semantically-valid reuse lookup follows

SPECULATIVE
  branch is discarded
  State dependent-lifecycle set becomes TERMINAL
  no reuse lookup
```

Again, this is a State dependent-set update, not resurrection of the same WAITING Continuation. Remaining required branches become terminal during cleanup and the Session ends. This uses the existing C7.1 `speculative_fraction` axis without introducing an unfrozen waiting:active tuning parameter. The full produced branch set defines the common reference working set before resolution.

## Reuse-token and TTFT projection

Every eligible reuse opportunity carries exactly 1024 full-context / reusable-prefix tokens. This is the C7.1 `recompute_tokens` reference design point, reused as a P-SRC4 metric-projection constant rather than added as a new P2/P3 sweep axis.

```text
hit   consumed_reuse_tokens = 1024
miss  consumed_reuse_tokens = 0
```

P2 Tool-Return TTFT uses `full_context_tokens=1024`, the closed C6 runtime profile, exactly one first-decode step, and zero modeled queue delay. P3 does not invent a tool-return event.

Both accepted runtime profiles are retained:

```text
a100-80gb
h100-80gb
```

Residency/reuse outcomes are byte-defined and should be hardware-invariant; TTFT is reported per accepted C6 profile. Any observed non-timing hardware dependence is a mechanics error.

For a hardware-agnostic H5 claim triggered by Tool-Return TTFT, the same P2 cell must satisfy the frozen favorable comparison against all three primary retention baselines on both accepted source-model hardware-profile strata. A favorable TTFT result on only one profile is retained as hardware-stratum-specific descriptive evidence and cannot trigger H5. This remains source-model-derived timing evidence, not a direct hardware measurement.

## Metric estimators

The native metric definitions are preserved as ratios of aggregate numerators/denominators over Program clusters:

```text
USR = sum(useful resident byte-seconds)
      / sum(classified resident byte-seconds)

WSR = sum(wasted resident byte-seconds)
      / sum(classified resident byte-seconds)

RR  = sum(recomputed eligible-prefix tokens)
      / sum(prefill-equivalent tokens for eligible inference opportunities)

CCR = sum(cold eligible continuation executions)
      / sum(eligible continuation executions)
```

A Program with no tool return contributes zero numerator and zero denominator to P2 RR/CCR. It remains a Program cluster but does not manufacture an inference opportunity. A metric with zero aggregate denominator is labeled:

```text
INSUFFICIENT_METRIC_DENOMINATOR
```

rather than coerced to a performance value.

P2 Tool-Return TTFT is the arithmetic mean over the common policy-independent returning-Program subset. At least eight common returning Program clusters—the first frozen C7.1 convergence prefix—are required for inferential TTFT ranking. With fewer than eight, TTFT is descriptive only and cannot support H5.

Because every synthetic reuse opportunity is exactly 1024 tokens, RR and CCR are algebraically identical in this C7.3c construction. They are reported because both are frozen primary metrics, but they are correlated/redundant views of the same miss process and may not be presented as independent corroborating evidence.

Any semantic rejection excludes the affected result from efficiency ranking; semantic failure may not masquerade as speedup.

## Capacity infeasibility

`CAPACITY_INFEASIBLE` is an outcome, not a policy win. A B4-versus-baseline cell is numerically rankable only when all 64 paired Program realizations are capacity-eligible for both policies. Otherwise the comparison is labeled:

```text
INFEASIBLE_FOR_PAIRED_RANKING
```

and infeasibility rates are reported. Such a comparison cannot support H5. In particular, an infeasible session-pinning baseline is not converted into evidence that B4 wins.

## Statistics

C7.3c precommits to all 64 frozen seeds for every primary cell. C7.1 convergence prefixes:

```text
8, 16, 32, 64
```

are still reported diagnostically, but they do not stop this bounded C7.3c execution early. This is a fixed pre-result choice within the C7.1 maximum seed budget, not an outcome-dependent extension.

Uncertainty uses the frozen C7.1 paired nonparametric bootstrap:

```text
resamples       10000
seed            20260911
interval        percentile 95%
cluster unit    Program
```

Ratio metrics use paired Program-cluster resampling: the same sampled Program indices are used for B4 and baseline; each policy's ratio is recomputed from sampled numerator/denominator sums; then the paired difference is formed. If any required ratio bootstrap resample has zero aggregate denominator, that cell/metric interval fails closed as `INSUFFICIENT_METRIC_DENOMINATOR`; no resample is skipped, replaced, or regenerated.

TTFT resamples the common returning-Program subset. Bootstrap indices use a SHA-256 counter keyed only by schema, bootstrap seed, sample size, resample index, and draw index. Percentiles use Hyndman-Fan type 7 linear interpolation at 0.025 and 0.975. This removes Python/library RNG and quantile-version dependence without changing the frozen bootstrap design.

Difference orientation is always:

```text
LIFECYCLE_B4 - baseline
```

Favorable directions:

```text
USR                  positive
WSR                  negative
RR                   negative
CCR                  negative
Tool-Return TTFT     negative
```

A cell is statistically favorable only when the paired percentile-95 interval excludes zero in the favorable direction.

## H5 decision rule

The H5 hypothesis explicitly compares lifecycle-aware retention with all three ordinary baselines. The primary comparator set is therefore exactly:

```text
LRU
FIXED_TTL(5s)
SESSION_PINNING
```

TTL sensitivities and an optional oracle-tuned TTL envelope are supplementary. They cannot relax the three-baseline requirement.

For one metric, an H5-supporting cell must satisfy all of:

1. B4 and all three primary baselines are capacity-comparable for all 64 Program realizations;
2. no covered semantic violation occurs;
3. the paired 95% interval is favorable versus LRU;
4. the paired 95% interval is favorable versus FIXED_TTL(5s);
5. the paired 95% interval is favorable versus SESSION_PINNING;
6. for P2 Tool-Return TTFT, at least eight common returning Program clusters are available;
7. for P2 Tool-Return TTFT, the same cell satisfies items 1–6 on both accepted C6 hardware-profile strata.

An isolated point is insufficient. A `meaningful range` is a connected component of at least two immediately adjacent supporting cells on one frozen primary surface for the same metric. Adjacency changes exactly one surface axis by one neighboring frozen value.

Metrics allowed to trigger H5 support are:

```text
Useful State Residency
Recomputation Ratio
P2 Tool-Return TTFT
Cold Continuation Rate
```

Wasted State Residency is a complementary accounting diagnostic and may not independently trigger H5.

If no qualifying connected region exists, the outcome is:

```text
NOT_SUPPORTED_WITHIN_DECLARED_PHASE_SPACE
```

No familywise-error-rate claim is made beyond this predeclared region criterion. All cellwise intervals and the complete primary phase map are retained.
