## Independent source-semantic basis

The representation-v3 form is justified by the already-pinned Vidur implementation, not by the observed C6.4b residual vector.

Pinned source:

```text

model  meta-llama/Llama-2-7b-hf

```

The pinned `LinearRegressionExecutionTimePredictor` constructs `PolynomialFeatures()` followed by `LinearRegression()` and performs an upstream grid search over polynomial degree, include-bias, interaction-only, and fit-intercept choices. The source trains the compute components against `num_tokens`, cold-prefill attention against `(kv_cache_size, prefill_chunk_size_squared)`, and send/recv against `num_tokens` derived from byte size.

The pinned request/composition mechanics are also part of the source semantics:

- `Batch` rounds request-level compute tokens as `(n + 7) // 8 * 8`;
- KV-cache-save deliberately uses the exact token count rather than the rounded count;
- cold prefill from zero processed tokens has `kv_cache_size = 0`;
- `ExecutionTime.model_time` composes the per-layer component values, multiplies by the 32 Llama-2-7B layers in this TP1/PP1 domain, then converts milliseconds to seconds;
- CPU overhead is excluded by the accepted C6.4b source protocol, which uses `skip_cpu_overhead_modeling=True` and `ExecutionTime.model_time`;
- send/recv materialization is source-defined on integer predictor-token keys `1..4096` in the frozen protocol.

These implementation facts predate the C6.4b fresh evaluation. They therefore provide an independent structural basis for replacing request-level piecewise interpolation with a direct transcription of the source polynomial component models.

### Canonical source polynomial

Each source model is serialized as an expanded polynomial independent of sklearn runtime objects. A record carries:

```text
component identity
hardware identity
ordered feature names
lexicographically ordered non-constant monomial power tuples
one IEEE-754 binary64 coefficient per monomial
intercept with all constant-feature terms folded into it
upstream-selected hyperparameters
source/training reference
source protocol fingerprint
output unit = milliseconds
```

The CADI evaluator uses the serialized monomial order, scalar repeated multiplication for each exponent, and `math.fsum` for the intercept-plus-terms accumulation. It does not clip negative component predictions, smooth them, or otherwise alter source polynomial output. Non-finite evaluation fails closed. A composed physical cost must be finite and non-negative.

## Second untouched adequacy boundary

The boundary is selected by a deterministic timing-blind procedure. The selector reads only source identity columns required to reconstruct the old C6.3 request-level axes. It never reads or serializes timing columns.

Selection algorithm:

```text
selection_algorithm_id = sha256-four-per-equal-width-quartile-v1
selection_seed = cadi.c6.4c.boundary.v1|291fa8f9bd5c7d0e72e46163715cb04bd772d205
```

For each family:

1. begin from the source-declared identity domain `1..4096`;
2. remove every C6.3 request-level raw-reference axis for that family;
3. remove every previously frozen/observed C6.4a boundary axis;
4. divide the identity domain into `[1,1024]`, `[1025,2048]`, `[2049,3072]`, `[3073,4096]`;
5. rank candidates within each stratum by SHA-256 of `selection_seed|<reference-kind>|<identity-axis>`;
6. select the four lowest hashes in each stratum;
7. serialize the 16 selected public axes in ascending order.

For transfer the identity axis is the integer predictor-token key `k`; the public axis is `8192*k` bytes.
